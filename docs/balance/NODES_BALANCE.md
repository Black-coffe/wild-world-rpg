## 1. Методология

Бой узла **детерминирован** (`DamageService` без `mt_rand` — RNG только в пост-бойной лотерее трофея). Поэтому исход боя любого игрока против любого узла **вычисляется точно**, без шумных ручных прогонов. Калибровка сделана аналитической симуляцией, точно воспроизводящей формулы `NodeLevelCurve` + `DamageService` + цикл `runChunk`, и **сверена** с задокументированными в коде якорями кривой (HP L1=108/L50=500/L150=4500; dmg L1=13/L50=37/L150=87; armor L1=4/L50=24/L150=64 — совпадение точное).

Калибровка ведётся против **реального населения прода** (read-only срез 2026-06-23), а не против абстрактной модели.

## 2. Реальное население (прод, 2026-06-23) — переформулировка задачи

| Факт | Значение | Следствие для баланса |
|---|---|---|
| Активных персонажей (last_seen 30д) | **93** | Роудмеп-допуск «~147 reachable / 3-8 co-op» оптимистичен; со-оп-группы **пока нет** |
| Из них с экипированным оружием | **3 из 93** | **90/93 бьются КУЛАКАМИ** |
| Урон кулаков (`BattleCharacter` default `damage_value`) | **5** | Кулачник наносит ~4.8/раунд → не убивает почти ничего |
| HP-пул игрока | **100 (плоский потолок)** | Нет колонки `max_health`; `health` ≤ 100.00 у всех уровней. Выживаемость не растёт с уровнем — только броня экипировки |
| Распределение уровней | 467×L1 (~0 статов), тонкий хвост до **L207** (str 333) | Огромный разброс силы; ядро — свежие L1 |
| Урон оружия в БД | **4–45** (gated `required_level`, максимум req≤50) | Потолок игрокового DPS ограничен; топ-оружие dmg 45 |
| **Сид узлов (прод, 24 точки)** | **base_level L5–L44** (мин L5 @Y917, макс L44 @Y117) | **Входного L1-узла НЕТ.** Минимальный узел = **L5**; рамп L5→L44 юг→север; эскалация +40/килл (cap L84 у северных) |

**Главный сдвиг:** цель «L1 соло-валится» неактуальна (L1-узлов не сеется). Реальный **входной узел = L5**, и реальный кандидат на бой с ним — не свежий кулачник, а **подготовленный новичок** (есть оружие + несколько уровней).

## 3. Формулы и текущие дефолты (валидированы аудитом, mismatch'ей нет)

**HP узла** (кусочно-линейная): `L≤50: 100 + L·8`; `L>50: 500 + (L−50)·40`.
**Урон узла:** `12 + L·0.5`. **Броня узла:** `4 + L·0.4`, cap 110 (режет урон игрока на `armor/(100+armor)`).
**Урон (DamageService, boss-путь):** `final = max(base·0.5, base·(1 + clamp(Δlvl,±30)·0.02 + str·0.0025 + agi·0.0015)·(1 − armor/(100+armor)))`, где `base = damageValue` (кулаки=5; оружие ЗАМЕНЯет base). «Бутстрап слабого» (str<5 ∧ agi<5) для боссов клампится ≥1.0 (не ослабляет).
**Чанк:** `rounds_per_tap`=3 (игрок бьёт первым). **Реген:** `hp_regen_per_minute`=20 к max вне активного боя (пауза `regen_pause_minutes`=3 после удара; стоп при active encounter). **Откат захода:** `engage_cooldown_minutes`=5 → **реген за откат = 100 HP**.
**Трофей:** `soulbound_min_level`=50, шанс `min(0.35, 0.05 + L·0.002)` (L50=15%, L100=25%, L150=35%). **Золото:** `clamp(L·50, 100, 50000)` (L5=250, L44=2200, L84=4200).

Полный реестр ключей с `rationale/above/below` — в seed-миграциях `*Adr137*GameSettings*` (admin UI `/admin/game-settings?category=combat|world`). **Все дефолты сохранены без изменений** — анализ подтвердил их состоятельность.

## 4. Симуляция: исход соло-боя (профили прода × реальные сид-тиры)

Профили: **кулачник** (L1, str0.5, dmg5), **новичок+оружие** (L3, dmg12), **подготовл. новичок** (L5, dmg22), **мид** (L20, dmg40), **хай** (L60, dmg45), **элита** (L207, str333, dmg45). Все HP=100, плейн-атака.

| Профиль | Соло-доступный потолок узла | Заметка |
|---|---|---|
| Кулачник (90/93 активных) | **никакой** (LOSS даже L5) | by design: сперва нужно оружие |
| Новичок+оружие (dmg12) | **никакой соло** (L5 walled) | мало и урона, и выживаемости |
| Подготовл. новичок (dmg22) | **L5** (kill 7r / die 8r, впритык) | вход в боссинг; L6+ — LOSS |
| Мид (dmg40) | **L5–L14** | L20+ — walled |
| Хай (dmg45) | **L5–L40** | L44 — chips>regen (грань) |
| Элита (str333, dmg45) | **L5–L84 сид соло**; **L100+ — LOSS** | даже сильнейший не соло L100+ |

**Реген-гейт держит:** на верхних тирах соло-чип за один заход < 100 HP, что реген восстанавливает за 5-мин откат → соло не прогрессирует (WALLED). 3+ async-участника «Облавы» суммой обгоняют реген → узел падает.

## 5. Вердикты по 3 целям роудмепа

| Цель | Вердикт | Доказательство |
|---|---|---|
| **Вход соло-валится** | ✅ PASS | Входной L5-узел соло-валит подготовленный новичок (оружие ~22). Кулачники исключены **намеренно** (гейт «возьми оружие»; коммуницируется Осмотром 🟢/🟡/🔴 + предупреждением разрыва WB13 + /guide «начинай с тех, что по силам») |
| **L150/верх требует группу** | ✅ PASS | Никто из реальных игроков не соло-валит L50+; даже элита (str333) — LOSS на L100/L150. HP-губка seg2 (40/lvl) + реген-стена |
| **Соло-чип НЕ обходит реген** | ✅ PASS | На верхних тирах chip-за-заход < реген-за-откат (100) → WALLED |

**Итог: кривая фундаментально состоятельна. Ребаланс не требуется.**

## 6. Открытый вопрос — доступность входа (решение владельца)

Узкая соло-полоса (по сути 1 сид-узел L5 для подготовл. новичка) — это **намеренный гейт «подготовься»**, не баг: узлы — вызов эндгейм-наклона (раздел /guide в «Эндгейме»), а Осмотр + предупреждение честно сообщают силу ДО боя. Внутри node-only рычагов сделать узлы доступными кулачникам **нельзя** без их обесценивания (поднять урон кулаков = глобальная PvE-правка, вне scope WB15).

**Решение владельца (2026-06-23): оставить дефолты как есть, тюнить вживую в WB16** — калибровать против сегодняшней крошечной базы (90/93 кулаки) преждевременно; admin-tunable фреймворк существует ровно для живого твиддла по реальной вовлечённости.

### Готовые кандидаты на случай, если живые данные WB16 покажут вход слишком жёстким

| Кандидат | Изменение | Эффект (симуляция) | Высокий тир |
|---|---|---|---|
| **C1** | `combat.nodes.dmg_base` 12→8 | Подготовл. новичок соло L5–**L6**; меньше инстант-смертей у недоэкипированных | ✅ гейт цел (элита LOSS L100+) |
| **C2** | C1 + `hp_seg1_base` 100→70 | + входные узлы быстрее дохнут от скромного оружия | ✅ гейт цел |

Оба — node-only (глобальный PvE не трогают), реверсивны через admin/seed-миграцию.

## 7. WB16 live-tune playbook (что смотреть и каким рычагом крутить)

После активации `point_mode_enabled` — daily-наблюдение, и при сигнале крутить ТОЧЕЧНО через `/admin/game-settings` (admin-tunable, без редеплоя):

| Симптом на проде | Рычаг | Направление |
|---|---|---|
| Игроки гибнут на входном L5, 0 победных killов | `combat.nodes.dmg_base` | ↓ (12→8, кандидат C1) — меньше входного урона |
| Вход-узлы стоят неубитыми неделями | `combat.nodes.hp_seg1_base` / `hp_seg1_per_level` | ↓ — менее губчатые низы |
| Соло-игрок прогрызает верхний узел (гейт «группа» течёт) | `combat.nodes.hp_regen_per_minute` | ↑ (20→30) — крепче реген-стена |
| Узлы никто не находит/не пробует | онбординг/находимость (WB12-14) + анонс | — (не баланс) |
| Трофеи слишком редки/часты | `combat.nodes.soulbound_base_chance` / `_per_level` / `_max` | ↕ |
| Инфляция золота от Облав | `combat.nodes.gold_per_level` / `gold_hard_cap` | ↓ |
| Эскалация делает точку неубиваемой | `world.nodes.reincarnation_cap_per_band` | ↓ (40→меньше) |

**Инвариант при любом твиддле:** проверить, что верхний гейт цел (соло-чип < реген-за-откат на L100+) и что вход остаётся валимым подготовленным игроком. Симулятор (формулы §3) воспроизводим в любой момент.
