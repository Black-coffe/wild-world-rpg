# Запись игрока видна шире круга участников или хранит лишнее приватное

W2.N7 начал писать дуэли в общий журнал `battle_logs` строкой `DUEL`. Лог собирал тот же `PvpBattleLogBuilder`, что
у полевого PvP, и вместе с ним в запись попадали координаты обоих бойцов, хотя дуэль на арене от места не зависит.
А публичная страница `/battles/view/{id}` отдавала любую строку таблицы по номеру, без фильтра типа (публичный
список при этом показывал только PvP). Новая приватная запись автоматически становилась публичной.

## Цитаты владельца
- 2026-10-08 · w2-n7-combat, story 02 (ядро арены) · журнал дуэлей и `/battles/view` — «Дуэли теперь пишутся в журнал боёв, похоже, вместе с координатами обоих бойцов, а публичная страница боя открывает любую запись по номеру.»

## Cause
Новый тип записи положили в существующую таблицу и не проверили всех её читателей: в плане стояло «публичная
страница уже отдаёт любой бой — существующее поведение, не меняем». Строитель лога взят целиком, вместе с полями,
которые нужны полевому PvP (координаты), а новой записи — нет.

## Нельзя
- Писать новый тип записи в существующую таблицу, не пройдя всех её читателей (публичные страницы, списки, API, админка): кто увидит запись и какие поля.
- Оставлять публичный эндпоинт «по id» без фильтра, совпадающего с публичным списком (тип, владелец): перебор номеров открывает то, чего в списке нет.
- Сохранять приватные поля (координаты, клетку) в записи, которой они не нужны, — даже если вьюха их сейчас не показывает.

## Можно
- Публичная страница с тем же фильтром, что и список, и одинаковым 404 для «нет» и «не твоё».
- Записи, видимые только участникам, — через ядро с проверкой «мой бой» (`BattleJournalService::isMine`).
