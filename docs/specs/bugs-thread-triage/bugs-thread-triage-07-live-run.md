# Живой прогон: исполнить скрипты тапов волны 1

## Goal

Все пункты волны 1 с вердиктом `требует живого прогона` исполнены на preprod-testbot, каждый —
по правилу решения, которое доменный воркер записал заранее. Наблюдения и итоговые вердикты лежат
в `verdicts/live-run.md`; они старше доменных файлов и именно они попадут в отчёт.

## Requirements

> проходишь каждое сообщение или набор сообщений, чтобы контекст полный был, и смотришь: мы эту систему поправили, баг устранили?

> Если да, пишешь ответ, что данная система устранена, бага нет.

## Прогон на preprod ≠ «на проде»

Preprod-testbot катится с `develop`, прод стоит на `v0.51.666` и отстаёт на 60 коммитов
(`RECON.md`). Зелёный прогон на testbot доказывает, что правка **работает**, но не что игрок её
видит. Поэтому у каждого блока поле `На проде` заполняется отдельно:
`git tag --contains <sha> | sort -V | head -1` (тег не новее `v0.51.666`) либо прод-`SELECT`.
Работает на testbot, но тега нет → вердикт `исправлено, но не на проде`, а **не** `устранено`.
Доменный воркер мог этого не знать в момент написания скрипта — проверка на тебе.

## Что делать

1. Собери из `verdicts/*.md` все блоки с вердиктом `требует живого прогона` и их поля
   «Живой прогон» (предусловие · путь · правило решения — контракт C4 плана). Второй вид пункта —
   **перечитать вложение в полном разрешении**: скриншоты лежат локально (`DATA.md`), но три
   превью нечитаемы (`4294974474`, `4294974531`, `4294974565`) — их открывают в Telegram Web.
2. Исполни их на **preprod-testbot**: MCP Chrome + Telegram Web со второго аккаунта, тест-чар
   `telegram_user_id=25` (`aviad_echo`, char 491); текущий id сверь `SELECT id, name, level FROM
   characters WHERE telegram_user_id=25`. Автономная альтернатива, когда браузер не нужен, —
   POST на `https://testbot.wildworld.fun/telegram/webhook` с секрет-заголовком (`RECON.md`).
3. На каждый пункт напиши блок по `_FORMAT.md`: в «Чем доказано» — **что наблюдалось** (текст
   caption'а, подпись кнопки, ответ бота, вывод SQL), в «На проде» — тег или прод-`SELECT`,
   в «Вердикт» — результат применения правила решения, без собственной трактовки.
4. Правило решения не сошлось с наблюдением (экрана нет, путь не открылся, предусловие не
   собирается) — вердикт `не устранено` или `требует живого прогона` с объяснением, **никогда**
   `устранено` «по смыслу».
5. Бюджет кончился раньше пунктов — оставшиеся перечисли в конце файла разделом
   `## Не закрыто — не хватило прогона`, с их `mid`. Они уйдут владельцу во вторую часть отчёта.
   Это честный исход; выдуманное «устранено» — нет.

## Non-goals

- Не чинить: ни строки в `app/`, ни миграции, ни теста.
- **Не писать ничего в ветку «Баги и поломки» и вообще в группу `@wild_world_info`.** Telegram Web
  под аккаунтом Main открывается только на чтение вложения. Отправка — после «ок» владельца,
  её делает Queen.
- Не трогать прод: `wildworld-bot@…` — это ПРОД, там живые игроки и разрешён только `SELECT`.
  Все мутации — на `wildworld-testbot@…`. Перепутать user'ов уже стоило инцидента 2026-06-05.
- Не менять правило решения, записанное доменным воркером: не сошлось — так и напиши.
- Не переписывать чужие файлы `verdicts/*.md` — пишешь только свой.
- Не флипать килсвитчи `GameSettings`, если этого не требует предусловие пункта явно.

## Правила прогона

- Перед любой мутацией на testbot напечатай снимок «до» (`SELECT` затрагиваемых строк) и восстанови
  состояние после — даже если прогон упал.
- `characters.level` на testbot затирается пересчётом опыта: выставлять уровень напрямую бесполезно.
- Сессию Telegram Web не закрывай между итерациями: `select_page` → `take_snapshot` → клик →
  `take_screenshot`.
- Не запускай полный `phpunit` — общая тестовая база рвётся; нужен тест, гоняй одиночным файлом.
- Никаких `git stash` / `git checkout`: в репозитории параллельно работают другие.
