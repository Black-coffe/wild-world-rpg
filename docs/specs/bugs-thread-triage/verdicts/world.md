### `4294974544` — 2026-08-19 — Max Syskov

**Суть:** «А с какого уровня транспорт открывается?» → «у меня вообще не видно транспорта нигде»; владелец в `4294974547` в тот же день ответил, что транспорта в игре пока нет, позиции лежат в каталоге без открытого рецепта, а всё, что оказалось в инвентаре — ошибочный дроп с закрытым вчера краном.
**Вердикт:** устранено
**Чем доказано:** SELECT на проде — `game_settings.world.vehicle.enabled` = `value_bool=1` (`updated_at 2026-08-20`, на следующий день после жалобы). SELECT `crafted_items` (10 строк `type='transport'`): реальный путь крафта есть ровно у пяти — 43 «Легкая повозка»/LightCart, 46 «Тягловая повозка»/DraftCart, 47 «Горный велосипед»/MountainBike, 49 «Автономный дрон»/AutonomousDrone, 50 «Снегоход»/Snowmobile — все `status='active'` в БД **и** присутствуют ключом в `Config\CraftRecipes` (это и есть витрина `CraftedResourcesAction::TRANSPORT_VEHICLES`); `crafted_items.required_level` у них (10/20/12/25/20) — не тот источник, экран гейтит по `RecipeGateResolver`/`Config\CraftRecipes`/GameSettings (см. «Черновик ответа»), это отдельный, живой рассинхрон двух источников правды на одну сущность, не влияющий на вердикт. Отдельно id 42 «Плот» — строка `status='active'`, `required_resources`/`crafting_location` не пустые, но рецепта нет НИГДЕ в `Config\CraftRecipes` (grep по проду — 0 совпадений) и миграция `2026-11-29-100000_TransportCatalogCleanup.php:30` прямо говорит «не трогаем, заморожен за водным ADR»: активная строка БД ≠ достижимый предмет, поэтому его нет ни в витрине, ни в черновике. Та же проверка (`status='active'`, рецепта нет) — у id 44 «Парусник», 45 «Верблюд», 51 «Лодка с мотором», той же миграцией заморожены тем же комментарием. Id 48 «Воздушный шар» честно `status='deprecated'` и тоже без рецепта — нигде не обещан. Код витрины (`story transport-07`, `CraftedResourcesAction::transportShowcaseText()`) показывает раздел «🚚 Транспорт» с рецептами ЛЮБОМУ игроку, а не только тем, у кого он уже есть, — прямой ответ на «не видно нигде» (комментарий в коде цитирует именно этот класс UX-DISCOVERABILITY бага).
**На проде:** `git tag --contains` для всей серии `transport-01..07` (в т.ч. `a72a5156`, `a712d297`) → `sort -V | head -1` → `v0.51.635` ≤ `v0.51.666`; состояние killswitch'а подтверждено прод-`SELECT` выше (без него код мог бы быть на проде, но выключен — не тот случай).
**Живой прогон:** не нужен — прод-`SELECT` конфига и каталога рецептов исчерпывающее доказательство для killswitch-фичи без визуального рендера; браузер держит story 07.
**Черновик ответа:** Починили: транспорт открыт по-настоящему. Крафтится тут — *🎒 Инвентарь → 🔨 Крафтовые ресурсы → 🚚 Транспорт* — сейчас там пять машин: лёгкая повозка, горный велосипед, снегоход, тягловая повозка, автономный дрон. У каждой свой уровень, экран сразу покажет какой и чего не хватает. Часть машин крафтит только своя фракция: велосипед — Партизаны, снегоход — Милитари, тягловую повозку — Фермеры, дрон — Инженеры; лёгкая повозка открыта всем.
**Сомнения:** уровни намеренно не названы числом — они живут в GameSettings (`world.vehicle.*.required_level`) и правятся из админки без участия в этом вердикте, число в чате устареет и останется навсегда; на момент проверки прод-`SELECT` `game_settings` совпадает с дефолтом `Config\CraftRecipes` (6/12/14/14/16), но экран как раз и обязан показать актуальное значение сам.

### `4294974601` — 2026-09-03 — Анжела

**Суть:** «Ордината 0 не отображается» со скриншотом `4294974602` — карта-компас показывает игрока в (X=995, Y=1), большая светлая область сверху перед первой строкой с иконками.
**Вердикт:** не баг
**Чем доказано:** прогон на реальных данных (throwaway `php spark`-команда на testbot поверх боевых таблиц `map`/`explored_cells`, репозиторий не тронут, команда удалена после проверки) для клетки (995,1) и отдельно для клетки (500,0) — в обоих случаях `TextMapService::buildMapOnly()` рендерит строку ординаты 0 как валидную (`⬛️` неизученная или биом), а не пустой/пропущенной; вне границ мира (`worldY < 0` либо `worldX > 999`) рисуется отдельный символ `⬜`, визуально светлый и близкий к цвету неизученной ⬛️/биома-тундры на маленьком скриншоте. SELECT на проде подтвердил: `map` реально содержит 1000 строк с `coordinate_y=0` (границы мира `0..999`, не `1..1000`), и в области скриншота (`x 989–999, y 0–6`) biome_id=3 (тундра, ❄️) — 34 из 77 клеток, что совпадает со снежинками на самом скриншоте.
**На проде:** правка границ `1..1000` → `0..999` — коммит `430775f8` (2025-02-24) → `git merge-base --is-ancestor 430775f8 v0.51.666` → exit 0, живой на проде почти два года (`git tag --contains 430775f8 | sort -V | head -1` печатает не `v0.1.0`, а нехронологический тег `backup-website-2026-05-25` — проверка на `--is-ancestor` этим не сбивается); текущий код идентичен и на testbot, и в репозитории.
**Живой прогон:** не нужен — прогон на testbot по боевым данным карты уже показал построчный рендер; сам скриншот от игрока прилагается как второе прямое доказательство.
**Черновик ответа:** —
**Сомнения:** нельзя исключить, что путаницу создаёт визуальное сходство между «⬜ за пределами мира» и уже изученной тундрой «❄️» на маленьком скриншоте телефона — это вопрос читаемости карты, а не дефект рендера; отдельная тема для UX, не для этого вердикта.
