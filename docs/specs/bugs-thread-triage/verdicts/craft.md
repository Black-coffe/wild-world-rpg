# Вердикты: крафт, его экраны и одновременные задачи

### `4294974505` — 2026-08-10 — Анжела

**Суть:** нельзя запустить сбор ресурсов, пока идёт крафт на костре (готовка/консервация), но крафт на костре спокойно стартовал поверх идущего сбора — асимметрия правила «займёт целиком».
**Вердикт:** устранено
**Чем доказано:** код `ActiveTasksService::exclusiveConflict()` теперь вызывается и со стороны старта крафта (`GenericCraftActionStart::checkCanStartWithoutMaterials()`, коммит `126f05fb`, докстрока дословно цитирует эту жалобу и её направление) — прогон `vendor/bin/phpunit --no-coverage --no-progress tests/database/ExclusiveTaskLockTest.php` дал 10 passed / 18 assertions; SELECT на проде по `game_settings` (`craft.exclusive_lock.enabled`) — `value_bool = 1`, килсвитч включён.
**На проде:** `git tag --contains 126f05fb | sort -V | head -1` → `v0.51.605` ≤ `v0.51.666`.
**Живой прогон:** не нужен
**Черновик ответа:** Починили: сбор ресурсов и крафт на костре теперь блокируют друг друга одинаково в обе стороны — нельзя запустить один поверх другого, какой бы из них ни шёл первым.
**Сомнения:** направление подтверждено кодом, тестом и SELECT'ом killswitch'а, а не Tier-3 прогоном в живом Telegram — это делает story 07.

### `4294974610` — 2026-09-06 — Arseny

**Суть:** сапёрные лопаты, алмазные кирки и подобные T3-инструменты нельзя было крафтить по несколько штук за раз, в отличие от обычных инструментов (владелец ответил «Готово» в `4294974611`).
**Вердикт:** устранено
**Чем доказано:** `UtilityRecipePreviewT3Action::handle()` строит ряд кнопок количества через `CraftCardHelper::quantityRows($recipeKey, $maxAffordable)` вместо зашитой единственной кнопки «1 шт.» (коммиты `2b57d0ce`, `f2396e12`, спека `craft-quantity-parity`). Прогон `vendor/bin/phpunit --no-coverage --no-progress tests/unit/Craft/CraftQuantityParityTest.php` дал 11 passed / 41 assertion; тест называет именно `SapperShovel` и `DiamondPickaxe` — предметы из жалобы — и проверяет несколько ступеней количества при высокой доступности сырья, а не одну.
**На проде:** `git tag --contains f2396e12 | sort -V | head -1` → `v0.51.663` ≤ `v0.51.666`.
**Живой прогон:** не нужен
**Черновик ответа:** Готово: у *Сапёрной лопаты* и *Алмазной кирки* теперь тоже есть ряд кнопок количества в карточке крафта — как у обычных инструментов.
**Сомнения:** починка этих двух предметов устояла, но у неё есть непереехавшие братья того же класса: grep `craftCardHelper->quantityRows` по `app/` даёт единственное совпадение — `UtilityRecipePreviewT3Action.php:251`; `MedicalRecipePreviewT3Action.php:235`, `ArmorRecipePreviewT3Action.php:273` и `WeaponRecipePreviewT3Action.php:268` до сих пор жёстко печатают «🛠 Скрафтить 1 шт» с колбэком на одну штуку. Медицина T3 — тот же стакающийся расходуемый класс, что инструменты из жалобы; спека-первоисточник (`docs/specs/craft-quantity-parity/craft-quantity-parity-01.md`, Non-goals) сама называет причину — «НЕ мигрировать остальные ~27 карточек крафта на новый метод... Трогаем только T3-экран» — это осознанно суженный черновик, а не забытая правка, но хвост класса «T3-карточка не даёт партийный крафт» этим не закрыт. Фиксирую как незакрытый хвост, не повод переоткрывать эту жалобу.
