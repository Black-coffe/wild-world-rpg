# E-FIRST — первый экран новичка без конкурента (plan)

**Tier:** 2 · **Spec slug:** `e-first` · **Brief:** [brief.md](brief.md)
**Governed by:** ADR-103 (онбординг и устойчивость навигации), ADR-150 (каркас меню, пере-аттач), ADR-168 (метка `origin`), ADR-190 (нейтральное ядро первого экрана — `ColdOpenWelcomeService`)
**Depends on:** `w-reg-polish` (v0.51.703), `web-onboarding` (v0.51.698); данные — `docs/specs/d-srez/report.md` §3

## Goal
Убрать конкуренцию двух инструкций на первом экране бота: до первого шага внизу у новичка одна кнопка, ведущая туда же,
куда экран Роби, а полное меню приезжает сразу после первого шага — один раз, с объяснением. Ядро первого экрана
(`ColdOpenWelcomeService`) решает, какая клавиатура у носителя; рендерер бота её только отправляет. Веб не трогаем.

## Assumptions
- «Первый шаг» = первый `move` с меткой `origin = 'cold'` (inline-кнопка Роби или новая нижняя кнопка). «✏️ Назвать героя» шагом не считается — меню после имени не приезжает, нижняя кнопка остаётся.
- Полное меню после шага шлётся ПОСЛЕ ответа компаса, отдельным сообщением (reply-клавиатуру нельзя повесить на edit) — по образцу `NavMenuRefreshService::maybeRefresh`.
- Новичок, который так и не сделал шаг, остаётся с одной кнопкой; `/start` и `/menu` возвращают полное меню (существующая ветка `StartCommand.php:127-131`) — это и есть запасной путь.
- Флаг сидится миграцией со значением 0 (как прочие флаги онбординга); включение на проде — через админку после зелёного preprod-смоука.
- `GAME_DESCRIPTION.md` первый экран построчно не описывает — канон-синк не нужен (проверить grep'ом при сборке; если описывает — строкой в Plan deltas).

## Stories

**Wave 1**
- `e-first-01` — одна нижняя кнопка «🧭 Сделать первый шаг» на первом экране + её текстовый роут в первый шаг с `origin = cold`, флаг в GameSettings.

**Wave 2**
- `e-first-02` — полное меню один раз после первого шага (маркер в `action_log`), tech-writing, cold-smoke.

## Contracts
- Подпись кнопки — одна константа (источник истины в `ColdOpenWelcomeService` или `BotMenuService`), её читают и клавиатура, и роут в `GenericmessageCommand` — текст кнопки и case не разъезжаются.
- Маркер one-shot: `action_log.action_name = 'FirstStepMenuAttached'`.

## Success threshold (объявлен до релиза)
База (прод, новички 02.10–30.10, n = 23): первый шаг (`move`) за 24 ч — **26 %** (6 из 23); медиана тапов за 24 ч — **5**.
После включения флага, по первым ≥ 20 новичкам: **успех** — первый шаг ≥ 45 % **и** медиана тапов ≥ 8. **Откат флага —
только при явном вреде** (решение владельца 2026-11-01): из первых 20 первый шаг сделали **≤ 2**, иначе по первым 40 — **≤ 6**.
Между ними — держим и меряем. Почему не «ниже 26 % из 20»: при нулевом эффекте такое правило откатывает в 58 % случаев,
а при настоящем росте до 35 % — в 25 %. Новое правило ложно откатывает при нулевом эффекте около 8 %, а падение до 10–15 %
ловит по 40 новичкам в 61–90 % случаев (биномиальный расчёт). **Первый шаг** = `move` с `origin = 'cold'` **или** строка firehose
`source = 'text'`, `action_name = '🧭 сделать первый шаг'`, `origin = 'cold'` (нижняя кнопка). Считать по всей когорте, не по «ушедшим в меню»
(самоотбор). SQL — `docs/specs/d-srez/report.md` §3 и этот план.
