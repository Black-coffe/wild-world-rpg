# Brief: web-onboarding

**Date:** 2026-10-11 · **Tier:** 3 (сквозная: бутстрап /play, cold open бота → ядро, входящие, экран задач, кабинет) · **Track:** ROADMAP W-REG · **Source study:** [w-reg-cold-pass/report.md](../w-reg-cold-pass/report.md) F1, F2, F3, F5

## Request (verbatim)

> /vulyk-plan одной спеки «веб-онбординг» в общем ядре: приветствие, итог задачи на экране, шаги обучения не только во входящих, переход сразу в игру. Пункты 1–3 — одна проблема (веб не показывает того, что бот показывает в ленте), и чинить их порознь значило бы трижды переделывать первый вход в игру.

## Context (из study, с доказательствами — report.md)

- F1: веб-новичок не получает cold open — `AccountRegister.php:85` выбрасывает `CharacterProvisioningService::lastTexts()`; бутстрап `/play` шлёт мостом `/start` (`WebActService.php:44`) → ветка существующего игрока `StartCommand.php:265` («🧭 Меню ниже.» `:278`).
- F2: законченная задача (добыча) остаётся на экране с «❌ Прервать добычу», итог — только во входящих, после крона.
- F3: сообщения обучающей цепочки (закрыт шаг, награда, следующий шаг) — только во входящих под 🔔, задержка крона до 60 с.
- F5: после создания персонажа — `/account` (`AccountRegister.php:93`), не `/play`; первый `/play` >10 с.
- ADR-190: экран = сервис ядра + два тонких рендерера; бот переписывается под ядро в той же W-спеке, мост — только фолбэк.

## Answers

1. **Приветствие** — Первый экран при создании (Рекомендую): Общий сервис ядра собирает приветствие из текстов создания и сразу кладёт его первым экраном /play с кнопкой «🧭 Сделать первый шаг»; бот рисует тот же текст. /start через мост при первом входе больше не гоняется, поэтому заодно уходит загрузка >10 с и «Меню ниже».
2. **Новое** — Баннер + замена залипшего (Рекомендую): Новое сообщение появляется плашкой над экраном целиком, с кнопками, не сбивая текущий экран; а если на экране висит уже законченная задача — он сам заменяется её итогом. Опрос входящих уже идёт раз в 30 с, его и используем.
3. **Требования** — Верно, покажи план (Рекомендую): Четыре требования как есть; сборка — после твоего «да» по плану.

## Asks

1. Веб-новичок при первом входе видит приветствие Роби — тот же первый экран, что бот даёт в ленте (паёк, сигнал, встречающий, «🧭 Сделать первый шаг»), собранный в общем ядре, и бот рисует его из того же ядра.
2. Итог задачи (добыча, крафт) — на экране: экран законченной задачи сам заменяется её итогом, без «❌ Прервать».
3. Шаги обучения (закрытый шаг, награда, следующий шаг) — не только во входящих: новое сообщение появляется плашкой над экраном, целиком и с кнопками.
4. После создания персонажа — сразу в игру (/play), а не в кабинет.
5. Бот после переноса первого экрана в ядро выглядит для новичка так же, как сейчас: тот же текст, те же кнопки и порядок сообщений при каждом сочетании флагов `onboarding.cold_open_v2.*` (проверка — тест на рендер бота до/после).
6. Экран читается в media-off: приветствие, итог задачи и плашка нового сообщения несут весь смысл текстом; в веб-текстах нового первого экрана нет бот-лексики («ниже», «нижнее меню», «команда /…»).
7. Вердикты: `/guide` — да/нет + раздел; совет — да/нет + категория; WipeManifest — для любой новой таблицы/колонки; tech-writing ноты на каждый тронутый сервис/контроллер; Tier-3 холодный проход по вебу на чистом аккаунте на preprod после зелёного `bash scripts/preprod-parity.sh`.
