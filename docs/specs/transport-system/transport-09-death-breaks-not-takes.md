# Смерть разбивает машину, но не забирает её

## Goal

Смерть перестаёт быть изъятием транспорта. Транспорт исключается из `computeCraftLoss`
(−3% с базой / −50% без), вместо изъятия износ активной машины обнуляется, указатель
нейтрализуется, игрок получает сообщение «повозка разбита — нужен ремонт». Строка владения
остаётся на месте. Это решение владельца (`brief.md → ## Answers`), оно **заменяет**
инвариант №9 в ADR-174, написанный до решения.

## Requirements

> Заворотить систему транспорта, начиная от крафта, логики, интеграции, доступности от разных уровней, и даже чтобы фракция влияла на транспорт.

## Следствие: транспорт уходит из крафт-страховки

Раз транспорт больше не изымается смертью, полис на него продаёт защиту от несуществующего
риска — ровно та ошибка, которую вскрыл ADR-172. Миграция убирает `transport` из
`craft_insurance.eligible_types` (`robots,workbench,transport,drones` → `robots,workbench,drones`),
идемпотентно и с обновлённым `rationale_text`. Проверено на проде 2026-08-19: застрахованных
транспортных строк **ноль** (при 8 верстаках и 10 роботах под полисами), то есть ни одна
оплаченная покупка не обесценивается и компенсировать нечего.

## Non-goals
- Не трогать долю потерь для остальных предметов (−3% / −50%) и дробный бросок ADR-172.
- Не выносить транспорт из `crafted_items_log` в отдельную таблицу ради «неотбираемости» — вопрос решён указателем (ADR-174 §1).
- Не менять `VehicleActivationService`: здесь только вызов готового `breakActive()` (story 03 — единственный владелец этого файла).
- Не изымать 21 грандфазерную строку и не «чинить» их задним числом.

## Acceptance criteria
- [ ] Позиции `type='transport'` не участвуют в `computeCraftLoss` ни в одной ветке (с базой и без): после смерти `quantity` строк транспорта не изменился.
- [ ] Смерть с активной машиной → износ этой строки 0, `active_vehicle_log_id` = `NULL`, строка на месте.
- [ ] Смерть без активной машины (или без транспорта вовсе) → поведение потерь байт-идентично сегодняшнему (ассерт на числа по остальным предметам).
- [ ] Игрок получает сообщение про разбитую машину, самодостаточное без картинки, с указанием пути к ремонту.
- [ ] Следующий Поход после смерти идёт с нейтральным профилем и **не блокируется**.
- [ ] Тест поведенческий: разыгрывается смерть, проверяются строки и указатель, а не наличие условия в коде.
