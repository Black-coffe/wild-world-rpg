## Asks

1. F4 — посадка (`PlantCropActionStart`) списывает семя условием «количество ≥ 1» с проверкой затронутых строк; при отказе
   транзакция откатывается, строка задачи посадки не создаётся, игрок видит отказ «У тебя нет семян…». Тест: запись при
   устаревшем снимке (семян 0 в БД, гейт пройден) не уводит количество ниже 0 и не создаёт задачу.
2. F8 — «Драться» и «Ограбить» (`NpcInteractionService::fight/rob`) выполняют бой/награду/перевод спавна в «мёртв» под
   `NamedLock` на этот спавн; второй вызов, пока лок занят или после смерти спавна, отвечает «NPC уже исчез.» и наград не
   выдаёт. `PvEService::attack` не меняется. Тест: при занятом локе — отказ без наград; после первого — второй без наград.
3. F9 — ремонт робота (`RobotRepairConfirmAction`), пакетный ремонт дронов (`RepairDroneRunAction`) и вклад во фракцию
   (`FactionProjectService`) списывают золото `decrementIfAtLeast` ДО ремонта/вклада; при `Refused` — откат, без ремонта и
   без вклада, существующий текст отказа. Прогресс проекта фракции — относительной записью. Тест: золота меньше цены в БД при
   пройденной проверке-чтении → золото не ниже 0, прочность/прогресс не изменены.
4. F10 — лут руин и поясных аномалий (`RuinLootService`) резервирует кулдаун условной записью ДО выдачи лута; лут — только
   при успешном резерве, иначе ответ `cooldown`. Тест: второй резерв в окне кулдауна отказывает без выдачи ресурсов.
5. F14 — препарат (`UsePharmacyAction`) списывает дозу условной записью ДО лечения, снятия дебаффов и «сытости»; при нуле
   — «препарат закончился» без эффектов. Тест: доза 0 в БД при пройденной проверке → здоровье и дебаффы не изменены.
6. F16 — мировые события (`IntentApplier`) применяют дельты здоровья, усталости, атрибутов и золота через
   `CharacterStatsService::adjust()` (пол 0.01 для здоровья/усталости/атрибутов сохранён, золото ≥ 0), ресурсы событий и
   потерю от метеора — относительной записью, не со снимка. Тест: две дельты подряд от одного снимка суммируются; минус
   золота больше баланса даёт 0, а не отрицательное число.
7. F21 — прерывание задачи (`FinishTaskAction`) применяет штраф только при успешном переходе `in_work → interrupted`
   (`transitionIfCurrent`); иначе — «Задача не найдена или уже завершена.» без штрафа. Тест: второй вызов на ту же задачу
   штраф не применяет.
8. F22 — `VehicleActivationService::activate()` возвращает `false`, если предмет владельца не разрешается в непустой ключ
   транспорта. Тест: не-транспорт отклонён, транспорт активируется.
9. F23 — рулетка смерти (`DeathRouletteHandler`) идёт под `NamedLock` на весь прогон, без миграции; второй одновременный
   прогон выходит, никого не обрабатывая. Тест: при занятом локе обработчик не вызывает смерть ни для одного кандидата.
10. F24 — обработчики роботов (`CompleteRobotGatheringHandler`, `CompleteRobotExplorationHandler`) не пишут статус задачи
    повторно (его атомарно ставит `Worker`); выдача ресурсов сбора — относительной записью (`increment`/`insertUnique`), не
    `quantity = снимок + n`. Тест: две выдачи от одного снимка дают сумму.
11. Опт — `bulkSellResources` проверяет результат `increaseGold`; при `false` — откат всей продажи и текст «Не удалось
    выполнить оптовую продажу…». Регресс-тест одновременного «🎒 Забрать всё» со склада базы: два забора от одного снимка
    выдают склад один раз. Тест на отказ `increaseGold`: ресурсы на месте, золото не изменено.
12. Телепорт — списание заряда (`TeleportItemConsumer`) и перемещение (`TeleportExecutor::teleport`) в одной транзакции в
    `TeleportUseAction` (рюкзак и портативный); сбой перемещения откатывает списание. Тест: исключение в перемещении
    оставляет заряд на месте.
13. `sellResource()` не трогается: закрыт хотфиксом 08.10 (сверено разведкой).
14. Вердикты: `/guide` — нет, совет — нет (новой игровой поверхности нет, меняются только тексты отказа гонок);
    GameSettings — нет (не баланс); WipeManifest — нет (новых таблиц и колонок нет). Tech-writing ноты каждой тронутой
    модели/сервиса/handler'а обновлены; ROADMAP: S2 удалён из §2/§4, строка в §6.
15. Регресс: полный набор PHPUnit зелёный, phpstan L9 зелёный; пофайловый набор `tests/exploit-poc/` даёт тот же список
    красных, что до спеки (ни одного нового красного, ни одной ошибки окружения).
