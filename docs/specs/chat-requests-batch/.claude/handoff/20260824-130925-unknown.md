### Принятые решения

**Владелец на стопе одобрения (все четыре — по моей рекомендации), записаны в `brief.md`:**

1. **Вход к сносу постройки — из списка построек базы** (`BaseBuildingsList::buildSummary`
   уже считает количество и суммарный налог; дубли видны именно там). Кнопку на экраны
   всех 17 построек НЕ добавляем — это 17 клавиатур и гарантированные разъехавшиеся близнецы.
2. **Ресурсы при сносе не возвращаются вообще.** Цена ошибки остаётся, возвращается только
   управление; иначе снос-постройка становится способом уходить от налога.
3. **Кулдаун на повторный снос — да**, ключ `GameSettings` с полной rationale (дефолт
   ставит Claude). Причина: налог собирается ежедневно в 03:00, без кулдауна цикл
   «снёс до сбора — построил после» становится выгодной схемой.
4. **Ступени количества на костре — те же, что у обычного крафта, плюс «своё число».**
   Не 1/5/50 из дословной формулировки заявки: два соседних экрана не должны вести себя
   по-разному.
5. **Охват логирования в story 05 — только налог и смерть** (допущение, владелец не
   возражал). Рейд и просрочка расходников — отдельным заходом после первого среза.

**Решения планирования:**

- **№7 разделён на две story** (05 write-side → 06 read-side, `blocked_by`), потому что
  экран, построенный на сегодняшних данных, показал бы игроку всё, кроме налога.
- **Метод сбора истории:** не листать чат руками, а выгружать DOM скриптом с прокруткой
  вверх и накоплением по `data-mid` — иначе Telegram выгружает историю кусками и часть
  сообщений теряется.

### Тупики и грабли

**Ложные предпосылки, которые пришлось отбросить (важное — не повторять):**

- 🔴 **«Данные для экрана „Куда ушло“ уже пишутся, новое логирование не нужно» — НЕВЕРНО.**
  Это было заявлено владельцу в артефакте и опровергнуто запросом на проде.
  `TaxCollectionHandler` списывает золото через `adjust()` в четырёх местах (~214, 253,
  306, 486) и **не пишет в `action_log` ни строки**; потерь при смерти там тоже нет.
  Пишутся: продажи/покупки/крафт/склад/дрон (`action_log`) и мировые события
  (`event_effects_log.effect_details`, JSON с `gold_delta` и
  `magnitude.resource_loss_percent`). Урок — `feedback_verify_premise_before_designing_defense`.
- 🔴 **Заявка №12 («после пропуска обучения не ведут в гайд») уже сделана** —
  `WithoutTrainingStartAction:49` давно несёт текст про «📖 Путь новичка» и саму кнопку
  (ADR-150). Жалоба игрока предшествует правке. Из плана исключена, строить нечего.
- **№2 не баг.** Охват робота считается линейно (`max(1, workshopLevel + extraCells)`), у
  Max Syskov L7 + T2-бонус = ровно 8 клеток, что совпало с его наблюдением. Чинить надо
  текст экрана, а не формулу; квадратичным охват НЕ делать.

**Технические грабли этой машины:**

- **Heredoc в bash рвётся** на кириллице/кавычках (уже был урок про CRLF и двойной
  бэкслеш). Многострочные файлы писать инструментом `Write`, а не `cat > f <<EOF`.
- **`scripts/*.sh` запускать только из корня репозитория** — из подкаталога спеки
  `bash scripts/wave-check.sh` даёт `No such file or directory`.
- **CDP-резайз и `emulate` не меняют layout viewport** в этом Chrome: `window.innerWidth`
  остаётся 981 при любом запрошенном размере. Проверять адаптив через **iframe с
  `srcdoc`** фиксированной ширины (`file://`-iframe даёт `contentDocument === null`).
- **Переключение веток форума в Telegram Web** через JS-клик по `.chatlist` не работает —
  нужен реальный клик MCP-инструментом по uid из снапшота. Снапшоты дорогие: снять один
  раз и переиспользовать uid'ы всех шести веток.
- **Локальный MySQL не поднят** (`Can't connect to localhost:3306`), тесты, ходящие в
  `wildworld_tests`, локально красные — это состояние машины, а не регресс. Для сверки
  фактов ходил в БД по SSH.

**Конвенции гейтов, на которых споткнулся:**

- `tests/database/` — **плоская**, подкаталогов нет. В `tests/unit/` существуют не все
  очевидные папки: есть `TaskHandlers`, `Camp`, `Craft`, `Player`, `World`,
  `Services/Onboarding`; нет `Robots`, `March`, `Onboarding`, `Economy`.
- Строка `## Verification` обязана называть путь, который **существует сегодня** и входит
  в `## Files`. Для новых тестов это невозможно, поэтому по конвенции репо там стоит
  `phpstan` по правимому исходнику, а требование написать тест вынесено в
  `## Acceptance criteria`.
