# Brief: w-reg-banner

**Date:** 2026-10-26 · **Tier:** 1 · **Track:** ROADMAP W-REG.5 · **Source:** смоук W-REG.3 (`docs/specs/w-reg-polish/smoke-preprod.md`)

## Request (verbatim)

> Дальше рекомендую W-REG.5

ROADMAP §4 (строка, на которую ссылается запрос):

> **W-REG.5** · Tier 1 · Баннер «Новое сообщение» (`app/Views/site/_play/banner.php`) при накопленных непрочитанных стоит
> над HUD и на 375 px занимает ~1460 px — экран игры уходит за первый экран до «Скрыть» (смоук W-REG.3, 26.10, Holodok:
> 23 непрочитанных). Решить: свернуть до одного сообщения + «ещё N», или показывать только новые с последнего визита.

## Recon (2026-10-26)

- Плашка уже ограничена: `WebInboxService::banner` (`app/Services/Web/WebInboxService.php:131`) отдаёт новейшие
  `WebPlay::$bannerMax = 3` непрочитанных, остальное — строкой «ещё N — во входящих 🔔». Высоту дают сами три
  сообщения: каждое рендерится целиком (фото, подпись, текст, все кнопки) — `app/Views/site/_play/banner.php`.
- Опрос `/play/inbox` раз в ≥10 с приносит `banner_html`, и `setBanner` в `public/assets/js/wildworld-play.js:64`
  каждый раз заменяет `#play-banner` целиком: состояние внутри плашки (раскрытое сообщение) пропадёт, если его не
  перенести.
- Стили плашки — `public/assets/css/wildworld-ui.css:1015-1023`; в `public/ui-kit.html` плашки нет (есть `.play-msg`).
  Кэш-бастинг: CSS `?v=16` (`app/Views/site/_layout/meta.php:72`), JS `?v=4` (`app/Views/site/play.php:71`).
- Тесты плашки — `tests/database/PlayInboxBannerTest.php` (полный текст и кнопки в HTML без JS, «ещё N», «Скрыть»).

## Answers

1. **W-REG.5** — Свёрнутые строки (Рекомендую): каждое из 3 сообщений — одна строка-заголовок (`<details>`, первая
   строка текста), тап раскрывает целиком с фото и кнопками; плюс «ещё N во входящих». Плашка ≈200 px вместо ~1460,
   ничего не теряется, работает без JS; в JS ~5 строк, чтобы раскрытое не схлопывалось при опросе.
2. **Десктоп** (вопрос в сборке, после замечания бокового агента) — Свёрнуто, самое новое раскрыто (Рекомендую):
   на ≥768 px самое новое сообщение раскрыто, остальные свёрнуты; на телефоне свёрнуто всё (раскрытое новое с фото
   снова увело бы экран игры); `open` ставит JS по ширине, без JS — всё свёрнуто.

## Asks

1. На 375 px с 3+ непрочитанными плашка «Новое сообщение» не выталкивает экран игры за первый экран: каждое сообщение
   плашки свёрнуто в одну строку (первая строка текста или подписи), «ещё N — во входящих 🔔» и «✕ Скрыть» на месте.
2. Тап по строке раскрывает сообщение целиком — фото, подпись, текст, все кнопки, — и кнопки работают через
   `/play/act` с `message_id`, как сейчас; без JS тоже (`<details>`).
3. Раскрытое сообщение не схлопывается, когда опрос `/play/inbox` приносит новую плашку (то же `message_id` остаётся
   раскрытым).
3a. На ≥768 px (с JS) самое новое сообщение плашки раскрыто, остальные свёрнуты; закрытое игроком сообщение опрос
   снова не раскрывает. На 375 px свёрнуто всё.
4. (ворота проекта) Media-off: строка-заголовок — текст, у сообщения только с фото без подписи и текста — нейтральная
   строка «Сообщение», не пустая. Сайт — только токены `wildworld-ui.css` (0 радиусов, 0 теней); свёрнутая плашка
   отражена в `public/ui-kit.html`; `?v=` CSS и JS подняты. Tier-2 смоук `/play` на 375/768/1440 на preprod: нет
   горизонтальной прокрутки, консоль чистая.
5. (вердикты) `/guide` — нет: это оформление веб-клиента, не механика. Совет — нет: игроку нечего узнавать, плашка
   объясняет себя сама. WipeManifest — не нужен: схема не меняется. Баланса нет.
