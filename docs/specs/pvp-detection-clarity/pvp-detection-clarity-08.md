# Гейт окна в атаке: экран ожидания вместо мгновенного боя, и база не теряет защиту при ответном ударе

## Goal

После story попытка атаковать игрока, стоящего на своей базе с живой обороной, открывает окно
противостояния и отдаёт атакующему экран ожидания с обратным отсчётом и двумя кнопками — «⏳ Проверить»
и «🚶 Уйти», — вместо немедленного боя. Блокируется атака именно по этой цели. Когда из окна бьёт
защитник, профиль обороны считается для владельца базы, а надбавка «укрыться» ложится под общий
потолок. При `pvp.standoff.enabled = false` путь атаки ведёт себя ровно как сегодня.

## Requirements

> А атакующий в этот момент ничего не может предпринять в течение пяти минут либо раньше, пока игрок как-то не среагирует.

> Логика и описание понимания в процессе встречи, атаки — всё должно быть учтено и в коммуникации должно быть видно, в том числе и ожидание пяти минут, чтобы всё-таки совершить нападение либо передумать и уйти.

## Non-goals
- Не блокировать атакующему прочие действия: запрет узкий, на пару (атакующий, защитник). Широкий запрет превращает окно в оружие защитника.
- Не трогать `PvpRoundOrchestrator` и `PvpDamageCalculator` — RNG-fence; надбавка «укрыться» едет существующим `damage_reduction`.
- Не менять `RunAwayAction` и не создавать «укрыться» — это `-09`, соседняя story той же волны.
- Не писать свои условные апдейты и не дублировать логику окна: всё через `PvpStandoffService` из `-06`.
- Не переносить кулдаун 30 с в `GameSettings`: ADR-186 §6 оставляет его в коде.
- Не запускать полный набор и не делать `DROP`/`migrate` на общей локальной тест-БД; не делать `git stash`/`git checkout`.

## Acceptance criteria
- [ ] Гейт окна стоит **до** записи анти-спам-кулдауна: взгляд на часы («⏳ Проверить», повторный тап) не стоит атакующему 30 секунд.
- [ ] При `pvp.standoff.enabled = false` путь атаки байт-в-байт прежний: строки в `pvp_standoffs` не пишутся, ни одного нового сообщения не уходит. Тест доказывает именно это.
- [ ] При включённом окне и защитнике на своей базе первая попытка атаки открывает окно, шлёт тревогу защитнику через `StandoffNotifier` и отдаёт атакующему экран ожидания: остаток времени, что может сделать защитник, две кнопки «⏳ Проверить» и «🚶 Уйти». Это не «⚠️ Ошибка», а lock-состояние с объяснением и путём.
- [ ] Пока окно живо, атака по **этой** цели отбивается тем же экраном; атака по другому игроку и любые прочие действия атакующего не затронуты. Отойти на клетку и вернуться — не обход: ключ окна пара, а не клетка.
- [ ] Когда окно истекло (проверка по времени, без участия крона), атака идёт обычным путём.
- [ ] «🚶 Уйти» закрывает окно как `cancelled`, защитнику сообщается, что нападавший ушёл; «⏳ Проверить» перечитывает состояние и перерисовывает экран.
- [ ] Если из окна бьёт защитник (`attackPlayer_<attacker_id>` при живом окне), окно закрывается как `countered`, а профиль обороны резолвится для **владельца базы** независимо от того, кто нажал кнопку.
- [ ] 🔴 **Добавлено главной сессией 11.09 из находки story `-07`.** Тап по кнопке-замку (`🔒 Уровень` / `🔒 Южная зона` / `🔒 Молодой аккаунт` из списка обнаружения) даёт игроку **объяснение, а не ошибку**: сейчас `AttackPlayerAction` префиксует ответ «⚠️ Ошибка:», хотя по правилу UX-DISCOVERABILITY клик по замку обязан объяснить условие и, где это возможно, назвать путь его выполнения. Текст берётся из `reason_code`, который уже несёт `PvPRestrictionService`. `-07` этот файл трогать не могла — он твой.
- [ ] 🔴 Ход «ударить первым» доходит от кнопки до боя: тап по кнопке тревоги из `-06` при живом окне **не** отбивается ни гейтом окна, ни 30-секундным анти-спам-кулдауном защитника, ни проверкой «атака по этой цели заморожена» — иначе третий ход владельца существует только в ENUM. Тест закрывает именно этот путь, а не только внутренний переход статуса.
- [ ] Надбавка `pvp.standoff.hold_damage_reduction_percent` применяется при статусе `held` и складывается **под** существующим потолком `defense.total_damage_reduction_max_percent` — тест доказывает, что потолок не пробивается.
- [ ] Полный список мест, откуда приходит `attackPlayer_`, получен `Bash`-грепом (`grep -rn 'attackPlayer_' app/`) и приведён в отчёте; гейт стоит в единственной общей точке `AttackPlayerAction::handle()`, а не у каждой кнопки.
- [ ] Все новые сообщения — HTML, экранированные имена, самодостаточный текст, кнопки по 2–3 в ряд.
- [ ] Тест строит схему из настоящих классов миграций и покрывает: килсвитч OFF, открытие окна, отбитый повторный тап, истечение по времени, `cancelled`, контратака с профилем владельца базы, потолок снижения урона.
- [ ] В `## Implementation notes` сказано: callback-поток и рендер экранов PHPUnit не видит — доказательство только Tier-3 двумя аккаунтами на testbot'е.
