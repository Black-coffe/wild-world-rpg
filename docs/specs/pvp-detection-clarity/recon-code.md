# Сводка разведки по коду, 2026-09-11

Четыре разведчика, только чтение. Все адреса ниже названы разведкой и должны быть перепроверены
воркером перед правкой — как обычно, отчёт разведки это указатель, а не истина.

⚠️ **Окружение:** во всех четырёх субагентах `Glob` и `Grep` по каталогу молча возвращали «ничего
не найдено» на заведомо существующих путях; `Read` файла и `Grep` с путём на конкретный ФАЙЛ
работали. Поэтому ни один разведчик не смог сделать репо-широкий грep, и списки вызывающих ниже —
«проверенные поимённо», а не «доказанно исчерпывающие». В каждой story воркеру надо давать точные
пути и требовать проверки через `Bash`-грep, а не через `Grep`-тул.

## B. Полевой PvP

`app/Controllers/Telegram/Commands/Actions/PVP/AttackPlayerAction.php`, callback `attackPlayer_<id>`

Гейты по порядку: атакующий найден (`:121`) → id валиден (`:125`) → цель найдена (`:129`) → не сам
себя (`:133`) → кулдаун 30 с (`:137-149`, `Config\GameBalance::$pvpAttackCooldownSec`, **хардкод**)
→ смежность клеток (`:151`, `isCellsCloseEnough` `:430-443`) → `PvPRestrictionService::checkPvPAllowed`
(`:155-159`) → карта/биом (`:161-168`) → профиль обороны (`:181-185`) → **сразу бой** (`:195`).

`app/Services/Player/PvPRestrictionService.php:30-80` — три гейта, **все три числа хардкод, мимо
`GameSettings`**, что нарушает конституционное правило admin-tunable balance:
1. `:33` — уровень любого из двоих < 5 → «Один из игроков имеет уровень ниже 5 — PvP недоступно.»
2. `:41-56` — любой из двоих в зоне высадки `coordinate_y >= 900` → запрет.
3. `:58-73` — любой аккаунт моложе 10 дней → запрет.

**`AntiCampService` в полевом PvP не участвует вообще** — он про world-boss loot-lock (ADR-137,
dormant). Исходное предположение задания было ложным.

**`characters.duels_open` в полевом пути не читается нигде.** Читается только в `DuelAction.php:99`
и в `PlayerDetectionService.php:226-238` (показывать ли кнопку «🤺 Дуэль»). Случай `sergiolamoz`
коду соответствует точно: «закрыт к дуэлям» не защищает от полевой атаки ни на йоту.

**Защитник до боя не получает ничего.** Единственное его сообщение — итог боя,
`AttackPlayerAction.php:381-394`. Окна «сбежать / ответить» нет. Кнопки «🏃 Бежать» / «⚔️ Атаковать»
из обнаружения принадлежат тому, кто ОБНАРУЖИЛ, а не обнаруженному. Канон
(`GAME_DESCRIPTION.md:60-66`) эту асимметрию подтверждает как замысел, а не как дефект.

**Уровень цели игроку не виден до нажатия «Атаковать»** — в сообщении обнаружения только имя и
дистанция. Отказ по уровню он узнаёт только после тапа.

**Что даёт база:** `app/Services/PVE/DefenseStructureService.php:57-128`, применяется только если
защитник стоит на своей клетке (`cb.map_cell_id = defenderCellNumber`) с активной (`hp>0`)
постройкой `building_type='defensive'`. Стена → снижение урона (клампится
`defense.total_damage_reduction_max_percent`, default 40), применяется
`PvpRoundOrchestrator.php:128-132`. Забор → урон атакующему за раунд (`:173-177`). Вышка →
бонус инициативы (`:294-301`). Износ после боя — `applyDecay()`, `AttackPlayerAction.php:198-200`.

## C. 🔴 Почему вышка молчала — найдено

`app/Services/PVE/TowerAlertService.php::notifyTowersNear()` (`:53-105`) жив и покрыт тестами
(`tests/database/TowerAlertServiceTest.php`, 7 тестов). Радиус — `GameSettings
defense.tower.alert_range_cells` (default 5), кулдаун `defense.tower.alert_cooldown_sec` (1800).
Постройка — `WatchTower` / «Дозорная вышка», `Config\Buildings.php:467-489`, уровень 12, налог 700.

**Единственный вызывающий — `app/TaskHandlers/MarchingTaskHandler.php:319-324`, то есть только
шаг Похода.** Обычное одноклеточное перемещение `MoveCharacterToDirectionAction` (callback
`move_dir_<direction>`) зовёт `PlayerDetectionService`, но `TowerAlertService` — **нет**
(проверено грепом по файлу: ноль совпадений).

Игрок в стенограмме сказал дословно «**Наступил рядом**» — то есть подошёл шагами, не Походом.
Значит вышка физически не могла сработать. Канон при этом обещает безусловно
(`GAME_DESCRIPTION.md:196`): «предупреждает тебя, когда поблизости появляется чужой игрок».
Это **обещание, которое код выполняет лишь на одном из двух способов приближения**.

Срабатывание вышки **нигде не логируется** (ни `action_log`, ни firehose) — измерить постфактум,
работала ли она когда-нибудь, нечем.

## D. «Партизанские» механики — их нет

Полнотекстовый поиск по всему vault'у (`партизан|скрытн|маскиров|стелс|незаметн|stealth|sneak|
guerrilla`) — ноль. При нашем документационном контракте это сильный сигнал, что механики
скрытности в игре просто нет, и вопрос игрока — разговорный оборот, а не отсылка к фиче.
Ответ игроку: подкрасться нечем, приближение видит (должна видеть) только вышка.

## F. Долг разведки закрыт главной сессией (рабочий грep)

104 tip-миграции, папка `app/Services/Onboarding/` — 16 файлов. Упоминание PvP во всём
онбординг-слое ровно одно: `GuideCatalog.php`. Отдельного just-in-time шага «в мире могут напасть»
нет ни одного.

**🔴 Худший из лживых текстов — совет, который бот САМ рассылает игрокам.**
`app/Database/Migrations/2026-11-07-110000_Adr164SeedFieldPvpTip.php:41-43`, категория «бой»,
`title_en = FieldPvpAndArena`:

> Не хочешь драк — держи тумблер *«Открыт к дуэлям»* в *«⚙️ Настройках»* выключенным.

Абзацем выше тот же совет честно говорит, что полевой бой начинается «если столкнёшься с другим
выжившим на карте», без всякого согласия. То есть совет противоречит сам себе внутри одного
текста — и заканчивается именно тем утверждением, в которое поверил игрок в стенограмме.
Это не просто раздел справочника, куда надо зайти: «Совет дня» приходит игроку сам.

Совет уже применён на проде — правка требует **новой** идемпотентной миграции, обновляющей
`content` по `title_en`, а не редактирования старой.

**Четвёртое обещание — на карточке постройки.** `app/Config/Buildings.php:471`, `info_text`
Дозорной вышки: «Предупреждает тебя о приближении чужих игроков…» — безусловно, без оговорки
«только если он идёт Походом». Игрок читает это, прежде чем заплатить 600 дерева и налог 700.

**В `/guide` про оповещение вышки не сказано вообще ничего** (упоминания «вышка» там — это
вышка связи и счёт дублей построек, другая тема).

Итого **четыре** текста формируют ожидание, которого код не выполняет: `GuideCatalog:958`,
совет `FieldPvpAndArena`, `Config\Buildings:471`, `GAME_DESCRIPTION.md:196`. Плюс
`SettingsAction` молчит там, где должен предупредить.
