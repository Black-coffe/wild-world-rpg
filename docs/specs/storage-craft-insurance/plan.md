# Склад перестаёт быть тупиком, страховка перестаёт врать (plan)

**Tier:** 3 · **Spec slug:** `storage-craft-insurance` · **Brief:** [brief.md](brief.md)
**Governed by:** ADR-059 (склад базы W3a), ADR-056 (страховка крафта V24), ADR-171 (новый — единый пул),
конституционные ворота `CLAUDE.md`: UX-DISCOVERABILITY, ONBOARDING/GUIDE/TIPS-COVERAGE, MEDIA-OFF,
ADMIN-TUNABLE BALANCE.
**Depends on:** `3431dc68` (рамка VULYK), прод `v0.51.630`.

## Goal

Три жалобы Анжелы — на самом деле два дефекта. **Первый:** склад базы построен как односторонний
приёмник. `BaseStorageModel` умеет `deliver()` и не умеет списывать; ни крафт, ни ремонт, ни апгрейд
построек, ни теплица не знают о его существовании. Отсюда и «крафт видит только рюкзак», и «теплица
не видит воду», и «забрать можно только всё» — один корень, три симптома. **Второй:** экран страховки
крафта показывает список того, что ещё МОЖНО застраховать, и при пустом списке говорит «у тебя нет
дорогих предметов» — то есть игрок, доведший механику до конца, получает сообщение, что механики у
него нет. Экрана действующих полисов не существует.

После спеки: пока игрок на базе, рюкзак и склад — один пул для трат (крафт, ремонт, стройка,
теплица), склад отдаёт ресурс по одному виду зеркально сдаче, а страховка показывает оплаченные
полисы и не сыплет английскими токенами.

## Assumptions

- **Крафт тратит со склада автоматически, а не просит перенести руками.** Анжела написала «крафт
  ингредиенты доступны только из рюкзака, даже когда я стою на складе, где их тысячи» — это просьба
  о едином пуле, а не о более понятном отказе. Порядок трат: сначала рюкзак, остаток — со склада;
  так игрок не удивляется тому, что вещи исчезают из хранилища, пока в кармане то же самое лежит.
- **Пул работает только когда игрок на базе** (`BaseCheckService::checkBaseStatus()['isOnBase']`) —
  единственный канонический критерий в проекте. В поле склад по-прежнему недоступен, иначе он
  перестаёт быть местом, куда возят дроном.
- **Радиус шире одного крафта — намеренно.** Ремонт и апгрейд построек содержат независимые копии
  той же «только рюкзак» логики. Правило проекта про class-of-bug (`feedback_twin_hotfix_grep`)
  требует чинить весь класс, а не тот экземпляр, на который пожаловались. Иначе через неделю
  приходит «а почему стройка не видит склад».
- **Выдача — по одному виду целиком, без ввода числа.** Анжела попросила «как у "положить на склад":
  выбор ресурса или забрать всё», а сдача устроена ровно так: `_res_<id>` кладёт весь вид целиком.
  Ввода произвольного количества в этом экране нет ни у одной стороны — зеркалим существующее, а не
  изобретаем новый элемент ввода.
- **Пул под killswitch'ем** `storage.pool_enabled` (GameSettings, категория `resources`). Механика
  меняет экономику трат на живом сервере; откат обязан быть тумблером в админке, а не релизом.
- **Тип `drones` в страховку не добавляю.** Карго-дрон, дрон-разведчик, боевой и ремонтный дроны
  застраховать нельзя, хотя они той же ценовой лиги. Это правка значения `craft_insurance.eligible_types`
  в админке, решение владельца, вынесено вопросом — не молча.

## Stories

**Wave 1**
- `storage-craft-insurance-01` — **tracer.** `ResourcePoolService` + `BaseStorageModel::withdraw()`:
  единая точка «сколько доступно» и «списать», killswitch в GameSettings.
- `storage-craft-insurance-02` — страховка: экран действующих полисов, честный empty-state,
  русские названия типов вместо `robots, workbench, transport`.

**Wave 2** (все `blocked_by: [01]`)
- `storage-craft-insurance-03` — склад: выдача по одному виду, зеркало сдачи.
- `storage-craft-insurance-04` — теплица пьёт воду из пула и не пугает нехваткой при полном складе.
- `storage-craft-insurance-05` — крафт считает и тратит из пула; экран нехватки называет склад.
- `storage-craft-insurance-06` — ремонт и апгрейд построек из пула (тот же класс бага).

**Wave 3**
- `storage-craft-insurance-07` — ворота контента: совет, раздел `/guide`, tech-writing, JIT-подсказка.

## Contracts

Решено здесь, потому что четыре story второй волны пишутся против этого интерфейса одновременно.

```php
namespace App\Services\Player;

final class ResourcePoolService
{
    /** Доступно всего: рюкзак + склад базы, если игрок на базе и killswitch включён. */
    public function available(int $characterId, int $resourceId): int;

    /** То же по имени ресурса — крафт оперирует именами из рецепта, не id. */
    public function availableByName(int $characterId, string $resourceName): int;

    /** Разбивка для текста игроку: ['backpack' => int, 'storage' => int, 'pooled' => bool]. */
    public function breakdown(int $characterId, int $resourceId): array;

    /**
     * Списать qty: сначала рюкзак, остаток — со склада.
     * @return array{backpack:int, storage:int} сколько откуда реально ушло
     * @throws \RuntimeException если доступного меньше qty (вызывающий обязан проверить available() заранее)
     */
    public function consume(int $characterId, int $resourceId, int $qty): array;

    public function consumeByName(int $characterId, string $resourceName, int $qty): array;
}
```

```php
// App\Models\BaseStorageModel
/** Частичное списание со склада; строка удаляется при уходе в ноль. Возвращает реально списанное. */
public function withdraw(int $characterId, int $resourceId, int $qty): int;
```

- Транзакции: `consume()` НЕ открывает свою транзакцию — вызывающие уже работают внутри
  `$db->transStart()` (крафт списывает в транзакции старта). Двойное открытие в CI4 даёт вложенность,
  которой здесь никто не ждёт.
- Killswitch `storage.pool_enabled` (bool, default `true`, категория `resources`): при `false`
  `available()`/`consume()` видят только рюкзак — поведение возвращается к сегодняшнему.
- Гейт «на базе» вычисляется ОДИН раз за вызов и не кэшируется между запросами.
