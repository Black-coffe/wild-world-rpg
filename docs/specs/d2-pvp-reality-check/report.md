(`ssh wildworld-bot@bot.wildworld.fun`), ничего не менялось. Срез — 2026-09-27 ~01:00.

## TL;DR

- **Полевой PvP жив, но это один человек.** За всю историю 11 боёв (все после ADR-164), 10 из них
  провёл Torch0010 (L342). С 12.09 — **ноль** боёв (15 дней).
- **Дуэли живы и растут.** 192 проведённых дуэли, 14 участников, но инициируют их 5 персонажей.
  Неделя с 25.09 — рекорд: 57 вызовов.
- **`pvp.standoff.enabled = 0` — забытый шаг, а не решение.** ADR-186 §7 планировал включение
  «через admin UI после Tier-3». Tier-3 прошёл на preprod 11.09, релиз v0.51.667 уехал 14.09 с
  флагом OFF, и флаг так никто и не включил. Записи «оставить выключенным» нет нигде.
- **E24 и E25 → DONE** (правка Приложения A — в этом же коммите).

## Ask 2. Почему `pvp.standoff.enabled` выключен

| Факт | Источник |
|---|---|
| Сид `false`: «включается отдельным флипом на testbot (Tier-3), а не автоматически с деплоем схемы» | `app/Database/Migrations/2026-09-11-210100_Adr186SeedStandoffSettings.php:13` |
| «Включение — через admin UI после Tier-3, прямой SQL обходит audit-trail» | ADR-186 §7 «Килсвитч» |
| «Окно выкатывается выключенным… включение — через admin UI после Tier-3» | `docs/specs/pvp-detection-clarity/plan.md:42` |
| Tier-3 на preprod: закрыты все четыре исхода окна (`held/cancelled/countered/expired`) | `mmorpg-vault/wiki/hot.md:38`, daily 2026-09-11 |
| Прод v0.51.667 (14.09): «`pvp.standoff.enabled=0`», спека влита без отдельной подписи, «тег develop целиком» | daily 2026-09-14 |
| На проде сейчас: `value_bool=0`, `updated_by=NULL`, `updated_at=2026-09-14 10:26:53`, то есть значение сида, руками флаг не трогали ни разу | `game_settings` |
| `pvp_standoffs` — 0 строк | прод |
| В `plan.md` строка `**Shipped:**` не заполнена | `docs/specs/pvp-detection-clarity/plan.md:244` |

**Вывод.** Флаг выключен потому, что так его засеяли (dormant-first), а последний шаг плана —
включить после Tier-3 — выпал. Спека уехала на прод в составе чужого тега («develop целиком»), и
её собственная стадия 06 не закрылась. Решения держать окно выключенным нет ни в ADR, ни в daily,
ни в hot.md.

Цена: 11.09 Torch0010 (L342) за 26 минут атаковал семь игроков L5–L89. Это ровно тот сценарий, ради
которого строился ADR-186 (жалоба sergey от 11.09). Тогда окна ещё не было в релизе. Сегодня оно
в релизе есть, но повторись такое завтра — не сработает, потому что выключено.

## Варианты по окну противостояния

1. **Включить `pvp.standoff.enabled` на проде через `/admin` (Рекомендую).** Tier-3 уже зелёный,
   прописанный в плане шаг просто выпал, а активность маленькая (0 полевых боёв за 15 дней), так
   что риск для живых игроков минимальный. Путь — admin UI, не SQL (ADR-186 §7, audit-trail).
   После флипа — прод-смоук только чтением: `pvp_standoffs` пишется при первой атаке у базы, в
   `player_action_log` нет ошибок.
2. **Включить с `pvp.standoff.require_tower = 1`.** Окно дают только базы с Дозорной вышкой.
   Мягче для атакующих, и у вышки появляется второй повод существовать. Но владелец в брифе
   ADR-186 сказал «база», а не «вышка».
3. **Оставить OFF до этапа II** (осады, ADR-186 в списке «решить при открытии»). Тогда это надо
   записать как решение в ADR-186, чтобы флаг перестал выглядеть забытым.

## Кандидаты в следующие спеки (не story-файлы)

1. **Флип окна** (вариант 1 или 2) + прод-смоук чтением + `**Shipped:**` в спеке
   `pvp-detection-clarity`. Tier 0, решение владельца.
2. **Гейт атаки в логе.** 10 тапов после 14.09 отбиты молча для аналитики: `status=ok`, причина не
   пишется. Писать код гейта в `player_action_log.error_text` (или отдельный `status`), чтобы
   следующий замер видел, где упирается PvP. Tier 1.
3. **Дуэльные «груши».** L2-аккаунты с открытыми дуэлями дают ~40 побед ядру. Проверить, это
   осознанный opt-in или хвост дефолта `duels_open`. Tier 1, после замера по `duels_open`.
