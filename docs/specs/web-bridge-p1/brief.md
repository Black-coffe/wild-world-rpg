**Source study:** [../web-first-client/report.md](../web-first-client/report.md) — §3 вариант A, §5 «Фаза 1 — мост» (B1–B7), §7 риски R4–R7
**Previous phase:** [../web-accounts-p0/plan.md](../web-accounts-p0/plan.md) — shipped v0.51.672 (ADR-188); хвосты — `mmorpg-vault/daily/2026-09-24.md` «Вопросы / завтра»

## Request (verbatim)

> Должна дальше по roadmap двигаться к полному переносу и дублированию возможности играть в игру на веб-сайте, и чтобы полностью разделить Telegram как связующее и зависящее звено. Мы уже это делали в прошлых сессиях. Давай продолжать, на чём мы остановились. Продолжай далее.

Контекст: Фаза 0 (аккаунт вне Telegram, вход, код `/web`, регистрация за флагом) на проде. «Продолжить, где остановились» по report.md = **Фаза 1 — мост**: игрок из аккаунта играет в браузере через те же маршруты бота (перехват транспорта `Request::setClient`), входящие вместо Telegram-пушей для web-игрока, канал `web` в логах. Открытый хвост Фазы 0: текст `/web` / совет / guide обещает привязку, которую код (F1) отклоняет.

## Answers

1. **Кто играет** — Виртуальный id: web-персонажу выдаём служебную запись с отрицательным id. В Telegram её нельзя отправить, все экраны бота работают без переписки. Сообщения на такой id уходят только во входящие на сайте. Переход на поиск по персонажу будет постепенно, в Фазе 2.
2. **Уведомления** — В оба места: для привязанного игрока сообщение как раньше уходит в Telegram, и копия ложится во входящие на сайте с колокольчиком. Бот не меняется, веб ничего не теряет. Web-only игрок получает сообщения только во входящие.
3. **Экран** — Экран + док: ответ бота показывается как один экран. Исправление сообщения становится сменой экрана. Меню бота превращается в нижний док, как в прототипе. Предыдущие экраны видны в короткой ленте сбоку или снизу. Так сразу закладывается основа для нативных экранов Фазы 2.
4. **Хвост Фазы 0** — Подтвердить + поправить текст: три правила (F1 без слияний, F2 один персонаж на аккаунт, F3 единый ответ сброса) остаются как сейчас. В этой же спеке текст `/web`, совет (новой миграцией) и guide будут говорить правду: «выйди из другого входа и введи код». Эти же тексты всё равно придётся дописывать про игру на сайте, поэтому делаем это одним заходом.
5. **Требования** — подтверждены владельцем; план показать до сборки (без straight-through).

## Asks

1. Вошедший на сайт игрок играет на `/play` через те же маршруты бота (кнопки, текстовые ответы, команды). По возможностям это то же, что бот, без второй реализации правил.
2. Персонаж без Telegram получает виртуальный id и играет наравне со всеми. На виртуальный id в Telegram ничего не уходит.
3. Ответ бота показывается как экран, а исправление сообщения заменяет экран. Меню бота становится нижним доком. Есть короткая лента предыдущих экранов. Фото идут с полной подписью, и экран понятен без картинки.
4. Фоновые сообщения: привязанному игроку уходят в Telegram и копией во входящие на сайте, игроку без Telegram — только во входящие. На сайте есть колокольчик со счётчиком.
5. Для игроков в Telegram бот работает как раньше.
6. В журнале действий есть канал `web`. Действия с сайта защищены (CSRF, лимит частоты), и игрок может управлять только своим персонажем.
7. Игра на сайте спрятана за флагом `web.play_enabled` в админке (по умолчанию выключен). Владелец включает его после проверки на preprod.
8. Текст `/web`, совет и /guide говорят правду о привязке и об игре на сайте. Совет обновляется миграцией, пишется тоном Роби, без чисел.
9. Вход в игру легко найти: «Играть» в шапке сайта и в кабинете. Пока флаг выключен, на этом месте видна понятная заглушка, а не пустота.
10. `/play` читается на ширине 375/768/1440 без горизонтальной прокрутки. Используются только токены `wildworld-ui.css`, новые компоненты заведены в `ui-kit.html`, в консоли нет ошибок.
11. Новые таблицы (входящие, виртуальные id) прописаны в WipeManifest.
12. На preprod персонаж, карта, сбор, крафт и входящие проходятся через `/play` — и привязанным игроком, и игроком без Telegram.
