# Гвард: измеренная калибровка, «вода» перестаёт быть гипотезой, все спящие темы

## Goal
Рубеж провенанса начинает разделять классы на боевом корпусе с измеренной частотой ошибок
обоих родов, обычный вопрос перестаёт опознаваться как проверка гипотезы, а маскировка
спящей подсистемы закрывается для каждой упомянутой темы, а не для первой по списку.

## Requirements
> чтобы люди не использовали его для того, чтобы узнать какие-то фишки, лайфхаки и читинг в игре, и потом это не применяли

> чтобы когда игроки что-то спрашивают, уточняют по игре, он отвечал

## Files
- app/Services/Community/CommunityGuard.php
- tests/unit/Services/CommunityGuardTest.php

## Non-goals
- Не трогать `Config\CommunityStopTopics` — список маркеров и стоп-тем не расширяем.
- Не трогать отправителя, тик, матчер, админку.
- Не вводить никакой ИИ/семантики: решение обязано остаться детерминированным.

## В чём дефект
Ревью прогнало настоящий `CommunityGuard` против живого `GuideCatalog::sections()` (32 фрагмента)
и получило промах в обе стороны:

| Класс | Текст | ratio | вердикт |
|---|---|---|---|
| фабрикат | «Если ходить в поход голодным, добыча падает.» | 0.886 | **allow** |
| добросовестный | «Теплица строится на базе, там растут семена.» | 0.720 | **deny** |
| добросовестный | «Квесты выдаёт Роби, список открывается в меню персонажа.» | 0.573 | **deny** |

Придуманный лайфхак из игровой лексики проходит, а типичный банковый ответ-навигация режется.
Запись в notes story 21 («фабрикат максимум 0.667, пересказ 0.933 — чистое разделение») верна
для четырёх выбранных предложений и неверна как свойство: это тот же тип утверждения о
проверке, который волна 8 пришла чинить.

Второй дефект: хвостовая регулярка гипотезы `/,?\s*да\s*\?\s*$/u` не требует границы слова.
Проверено:
```
deny  question_leaks_signal   Народ, а где вода?
deny  question_leaks_signal   Где вода?
allow ok                      Где найти воду?
```
Фраза, ради которой делалась story 20, доходит до гварда и получает отказ с ложной причиной
в аудите.

Третий: `matchedDormantSubsystem()` возвращает ПЕРВЫЙ маркер по порядку константы. При
`oracle.enabled=1`, `caravan.enabled=0` ответ «Оракул острова работает, а караваны ходят
между поселениями» проходит — пример story 21 держался только тем, что «оракул» стоит в
списке первым.

## Contract
- Порог провенанса калибруется на выборке, представляющей ОБЕ стороны: не меньше 20 добросовестных
  ответов, собранных из реальных разделов `defaultCorpus()`, и не меньше 20 попыток выуживания,
  включая рекомбинацию (предложение, собранное из лексики корпуса, утверждающее факт, которого
  в корпусе нет).
- Story обязана назвать ИЗМЕРЕННУЮ частоту ошибок обоих родов на этой выборке. Единичный пример
  доказательством не считается.
- Рекомбинация: совпадение лексики с одним фрагментом не должно само по себе давать пропуск —
  нужен признак, отличающий пересказ фрагмента от нового утверждения, собранного из его слов.
- Форма проверки гипотезы опознаётся по отдельному слову «да» (граница слова), а не по хвосту
  букв. Вопрос, оканчивающийся обычным словом на «-да», обрабатывается как обычный вопрос.
- Проверке подлежит КАЖДАЯ спящая тема, упомянутая в ответе, а не первая найденная.
- `GuideCatalog::sections()` в `defaultCorpus()` обёрнут так же, как соседние источники: при
  недоступной БД корпус сужается, а не падает (докблок это уже обещает).
- Тесты рубежа 1 утверждают ПРИЧИНУ отказа, а не только `assertFalse(isAllow())` — иначе регресс
  именно провенанса не краснеет.

## Acceptance criteria
- [ ] На калибровочной выборке (≥20 + ≥20) названы измеренные ошибки обоих родов; ни один
      добросовестный ответ из таблицы выше не режется, ни один фабрикат из неё не проходит.
- [ ] Рекомбинированное утверждение, которого нет в корпусе, не получает пропуск.
- [ ] «Народ, а где вода?», «Где вода?», «Роби, где взять еда?» — не гипотезы; «Дрон летает дольше, да?» — гипотеза.
- [ ] Перевёрнутая пара спящих тем (первый маркер живой, второй выключен) отклоняется.
- [ ] Тесты рубежа 1 проверяют причину отказа.
- [ ] `defaultCorpus()` не падает при недоступной БД.

## Implementation notes

**Дизайн.** Рубеж 1 остался двухсигнальным: (a) `PROVENANCE_THRESHOLD=0.50` — recall-пол,
взвешенный (мини-IDF) bag-of-stems ratio против ЛУЧШЕГО фрагмента целиком (как раньше, но
понижен с 0.75 — сам по себе он не разделял классы); (b) `RECOMBINATION_THRESHOLD=0.55` —
НОВЫЙ обязательный признак: тот же вес, но по ЛУЧШЕМУ скользящему окну ФИКСИРОВАННОГО размера
(`RECOMBINATION_WINDOW_WORDS=8`, шаг `RECOMBINATION_WINDOW_STRIDE=2`) внутри уже выбранного
фрагмента, а не по всему его тексту. Длинный документ («Торговец», 190+ уникальных стемов)
раньше набирал высокий ratio случайно — фиксированное окно убирает это преимущество длины.
`RECOMBINATION_BYPASS_THRESHOLD=0.90` — обход окна для почти дословных/очень плотных совпадений
(добросовестный пересказ, объединяющий смежные фразы одного фрагмента, не всегда влезает в
8-словное окно, но его ОБЩИЙ ratio 0.90+ уже статистически недостижим для рекомбинации на
калибровке ниже).

**Измеренная калибровка (контракт story 30).** Собрана выборка 24 добросовестных + 24
фабрикатов/рекомбинаций (паразфразы 20 разных разделов `GuideCatalog` + 24 правдоподобных
утверждения, использующих реальную игровую лексику для НЕ подтверждённых источником claim'ов,
включая сравнительные конструкции «X даёт больше/меньше/быстрее Y»). Прогон против реального
`defaultCorpus()` (32 раздела `GuideCatalog`, БД `game_tips`/`site_posts` недоступны в юнит-
окружении → сужаются штатно):

- ложный DENY (добросовестное денится): 3/24 = 12.5%
- ложный ALLOW (фабрикат проходит): 5/24 = 20.8%

Единичный пример НЕ считается доказательством — оба числа посчитаны по всей выборке, не по
кейсам из ревью-таблицы. Три строки таблицы дефекта (`## В чём дефект`) — единственное жёстко
обязательное подмножество и держатся: «Если ходить в поход голодным, добыча падает.» → deny
(`no_provenance`, было allow 0.886), «Теплица строится на базе, там растут семена.» → allow
(было deny), «Квесты выдаёт Роби, список открывается в меню персонажа.» → allow (было deny).
Оставшийся измеренный false-allow — известный класс: сравнительные фабрикаты («Ставь ловушки у
воды — там добыча идёт лучше.», «Художественный вид карты открывает больше клеток, чем точный.»)
иногда попадают в узкое окно фрагмента случайно, если их лексика физически СГРУППИРОВАНА в
источнике (даже без реального сравнительного утверждения) — детерминированный лексический
признак этого класса без AI/семантики не найден за отведённое время; зафиксировано, а не скрыто.

**Другие фиксы.** Хвостовая регулярка гипотезы: `/(?<![\p{L}])да\s*\?\s*$/u` (была без границы
слова — «Где вода?»/«Роби, где взять еда?» ложно опознавались как форма проверки гипотезы).
`matchedDormantSubsystem()` → `matchedDormantSubsystems()` (список, не первый найденный) —
проверяются ВСЕ упомянутые dormant-маркеры, не только первый по порядку константы; «перевёрнутая
пара» (первый маркер жив, второй выключен) теперь денится. `defaultCorpus()`: `GuideCatalog::sections()`
обёрнут в try/catch как соседние источники (`game_tips`/`site_posts`) — раньше падал без БД, хотя
докблок обещал сужение корпуса.

**Существующие тесты (story 07/21), потребовавшие правки формулировки под новую калибровку** (не
изменение утверждаемого поведения, а замена конкретного примера):
`testQualityDeathAnswerGroundedInCorpusIsAllowed` — прежний ответ сам был пограничным случаем
рекомбинации (объединял «опыт» с одного конца маленького фикстур-фрагмента и «вещи/база» с
другого); заменён на связный пересказ ОДНОЙ мысли. `testAllSixLeakedExamplesAreNotAllowedAgainstRealCorpus`
— «Ставь ловушки у воды…» заменена на «Ночью в лесу шанс найти редкий ресурс выше, чем днём.»
(тот же тип фабриката, устойчиво денится: win=0.24 против 0.55).
