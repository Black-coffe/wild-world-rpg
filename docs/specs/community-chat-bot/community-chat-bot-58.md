# Отправитель: полная проверка легаси-Markdown и отдельный аудит маршрута

## Goal
Отказ Telegram, вызванный содержимым текста, перестаёт быть вечным ретраем; отправка маршрута
отказа перестаёт выглядеть в журнале как ответ бота.

## Requirements
> чтобы когда игроки что-то спрашивают, уточняют по игре, он отвечал, коммуницировал, комментировал, чтобы была живая группа

> чтобы люди не использовали его для того, чтобы узнать какие-то фишки, лайфхаки и читинг в игре, и потом это не применяли

## Files
- app/Services/Community/CommunityChatSender.php
- tests/unit/Services/CommunityChatSenderTest.php

## Два дефекта, найденные ревью 2026-08-25

**1. Проверяется парность только `*`.** `CommunityChatSender.php:329` (`checkGates()`) ловит
непарную звёздочку, но отправка идёт `parse_mode=Markdown` (легаси, `:163`), где сущностей
больше: `_`, обратный апостроф, `[`…`]`. Текст банка с непарным `_` (слаг с подчёркиванием,
обрезанная скобка после правки владельца) уходит в сеть, Telegram возвращает `ok=false`, и
склейка возвращается в `'new'` — тик повторяет её каждую минуту вечно, каждый раз дописывая
строку в тот самый `admin_audit_log`, по которому считается часовой потолок. Ровно дефект 2
story 23, только через `_FAILED`, а не `_REJECTED`. Класс описан в уроке проекта
`feedback_legacy_markdown_no_backslash_escape`.

**2. Маршрут отказа неотличим от ответа.** Story 55 шлёт текст отказа гварда через тот же
`sendAnswer()`, который пишет в аудит `COMMUNITY_ANSWER_SENT`. В результате отказ считается
ответом бота в главной метрике плана (`/admin/community`), и одно сообщение попадает в обе
половины: `guardTotal = botAnswers + guardDenied` учитывает его дважды.

## Контракт для смежных story (не менять в одиночку)
Заводится `sendGuardRoute(int $selfId, string $text): bool` — то же поведение, что у
`sendAnswer()` (гейты, потолок, реплай в топик), но аудит-действие **`COMMUNITY_ROUTE_SENT`**.
`CommunityAutoReplyHandler` переходит на него в story 57, `/admin/community` перестаёт считать
его ответом бота в story 59. Имя действия — часть контракта, не переименовывать.

## Non-goals
- Не выводить отказ гварда из-под часового потолка топика: это осознанно — иначе тот, кто
  целенаправленно выуживает читы, получает гарантированный текстовый ответ на каждую пробу.
- Не переходить на `MarkdownV2` и не менять `parse_mode` — это отдельное решение с миграцией всех
  текстов банка.
- Не трогать `CommunityAutoReplyHandler` (story 57) и админку (story 59) — только отправитель.
- Не трогать гвард и его пороги.

## Acceptance criteria
- [ ] Текст с непарным `_`, обратным апострофом или `[` отклоняется гейтом до сети, с той же причиной-классом, что и непарная `*`.
- [ ] Отклонённая по содержимому склейка получает **терминальный** статус, а не возврат в `'new'`; повторного захода тика по ней не происходит.
- [ ] `ok=false` от Telegram по причине, связанной с содержимым текста, тоже терминален; транзиентные сетевые отказы по-прежнему ретраятся.
- [ ] `sendGuardRoute()` пишет `COMMUNITY_ROUTE_SENT`, `sendAnswer()` — `COMMUNITY_ANSWER_SENT`.
- [ ] Часовой потолок топика считает **оба** действия — «сколько раз бот открыл рот», безразлично зачем: маршрут и уважает потолок, и пополняет его. Тест: серия маршрутов исчерпывает потолок и глушит следующий маршрут.
- [ ] Метрику «доля ответов бота» это не затрагивает — она считает только `COMMUNITY_ANSWER_SENT` (story 59).
- [ ] Тест на вечный ретрай краснеет, если терминальность убрать.

## Implementation notes

- `app/Services/Community/CommunityChatSender.php` — `checkGates()`: `substr_count($text, '*') % 2`
  заменён на `hasUnbalancedMarkdownEntities()` (`:369` gate call, метод в `:377`) — парность
  `*`/`_`/`` ` ``, плюс сравнение количества `[` и `]`. Причина осталась той же строкой
  `unbalanced_markdown` — уже в `TERMINAL_GATE_REASONS` у `CommunityAutoReplyHandler`
  (вне `## Files`), поэтому терминальность для дефекта 1 (парность) заработала БЕЗ правки
  вызывающего.
- `dispatch()` (`:219`): при `ok=false` метода `sendMessage` с описанием, содержащим
  `can't parse entities` (формулировка Telegram общая для legacy `Markdown` и `MarkdownV2`),
  пишет `{prefix}_REJECTED` с причиной `unbalanced_markdown` вместо `{prefix}_FAILED` — та же
  терминальная причина, тот же путь у вызывающего, снова без правки `CommunityAutoReplyHandler`.
  Решение: не трогать `TERMINAL_GATE_REASONS`/`resolveFailure()` (вне `## Files`), а подогнать
  ИМЯ действия/причины под уже существующую там терминальную классификацию — контракт
  `_REJECTED` = детерминированный отказ гейта уже был в комментариях `resolveFailure()`.
- `sendGuardRoute(int $selfId, string $text): bool` добавлен (`:152`) — контракт story:
  сигнатура и имя действия `COMMUNITY_ROUTE_SENT`/`_REJECTED`/`_FAILED` не переименовывались.
  `sendText()` (`:158`) рефакторен: вместо `bool $isManual` определяющего `$auditPrefix` внутри —
  теперь принимает `$auditPrefix` явным параметром (третий способ вызова, `COMMUNITY_ROUTE`,
  добавился без веток if/else). `sendAnswer()`/`sendManualAnswer()` обновлены под новую сигнатуру.
  Гейты `sendGuardRoute()` — те же, что у `sendAnswer()` (`$isManual=false`): килсвитч, потолок,
  кулдаун, длина, парность, канон — не ручная льгота.
  Правка по замечанию лида (2026-08-26): счётчики `sentInTopicLastHour()`/`authorSentWithinCooldown()`
  теперь считают И `COMMUNITY_ANSWER_SENT`, И `COMMUNITY_ROUTE_SENT` (`WHERE a.action IN (...)`).
  Первая версия считала только `COMMUNITY_ANSWER_SENT` — маршрут уважал потолок, но не пополнял
  его, а это открывало заднюю дверь: тот, кто целенаправленно выуживает читы, получал бы
  гарантированный текстовый ответ на каждую пробу, потому что счётчик от его собственных отказов
  никогда бы не рос (вектор спама, запрещённый `## Non-goals`). Потолок топика и метрика «доля
  ответов бота» — два разных счётчика: первый («сколько раз бот открыл рот») теперь общий для
  ответа и маршрута, вторая (только `COMMUNITY_ANSWER_SENT`, story 59, вне `## Files`) не
  трогалась.
- `"can't parse entities"` вынесен в именованную константу `TELEGRAM_CONTENT_PARSE_ERROR_MARKER`
  (`:76`) с комментарием, что матч хрупкий (формулировка Telegram не документирована) и как
  заметить поломку.
- `tests/unit/Services/CommunityChatSenderTest.php` — 3 новых теста на парность
  (`_`/`` ` ``/`[`), 2 теста на терминальность `ok=false` (контентная причина → `_REJECTED`,
  сетевая → по-прежнему `_FAILED`, дублирует существующий `testTelegramNotOkDoesNotThrowAndIsAudited`
  сознательно — разные формулировки одного инварианта), 3 теста на `sendGuardRoute()`
  (собственное действие, уважает потолок топика, отказ по содержимому пишет `COMMUNITY_ROUTE_REJECTED`
  а не `_ANSWER_*`).
- Не проверял через `vendor/bin/phpunit` — параллельно работают другие воркеры на общей
  `wildworld_tests`, команда лида явно запретила запуск. Проверено `php -l` на обоих файлах.
