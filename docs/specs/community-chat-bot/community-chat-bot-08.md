# Банк ответов и матчер: два порога, кулдауны, склейка дублей

## Goal
Появляется механизм, который сопоставляет вопрос игрока с утверждённым ответом из банка
и решает, отвечать ли сейчас, позже или никогда. Порог для адресного обращения низкий,
для подслушанного — заметно выше: перебивание живых людей дороже пропущенного ответа.

## Requirements
> когда игроки что-то спрашивают, уточняют по игре, он отвечал

> Тут нужно спланировать, как он будет отвечать: автоматически, в ручном режиме, полуавтоматически

> Двухскоростной: мгновенно на знакомое, отложенно на новое

## Non-goals
- Не отправлять — отправка через `CommunityChatSender` (story 06), вызывает её story 09.

- Не наполнять банк: банк пуст на старте и наполняется в обкатке через админку.

## Contract (из plan.md §4)
- `match(CommunityMessage $m): Decision` → `answer_now` / `answer_after_delay` /
  `receipt_only` / `silent`.
- **Полоса A (адресное, `addressed_to_bot=1`):** порог `threshold_addressed`. Совпало —
  `answer_now` (задержка 0, перебивать некого). Не совпало — `answer_now` с утверждённым
  `CommunityVoice::UNKNOWN` («Не знаю точно. Передал вопрос разработчику») + строка
  помечается `escalated`. **Молчание в ответ на прямое обращение запрещено.**
- **Полоса B (подслушанное):** порог `threshold_overheard`, заметно выше. Совпало —
  `answer_after_delay` (`delay_seconds`). Не совпало — `receipt_only` (реакция 👀) и строка
  копится как открытый вопрос.
- Выдержка полосы B отменяется, если за время ожидания в том же топике появился ответ
  человека на то же сообщение. Это признанный компромисс: полоса B намеренно не мгновенна.
- Запись банка не участвует в матче, если: `status != 'approved'`, ИЛИ `revoked_at`
  заполнен, ИЛИ `approved_at` старше `community.answer.max_age_days` (срок годности —
  игра меняется, банк молча устаревает и тогда бот врёт с полной уверенностью).
- Вопрос старше `community.question.max_age_hours` публично не отвечается.
- **Склейка дублей:** если несколько открытых вопросов в одном топике матчатся на одну
  запись банка, отправляется ОДИН ответ, адресованный всем, а не пять сообщений подряд.

## Acceptance criteria
- [ ] Адресный вопрос без совпадения → `answer_now` с текстом `UNKNOWN`, строка `escalated`.
      Никогда `silent`.
- [ ] Подслушанный вопрос со сходством между двумя порогами → `receipt_only`, не ответ.
- [ ] Подслушанный вопрос выше `threshold_overheard` → `answer_after_delay`.
- [ ] Ответ человека в тред во время выдержки отменяет отправку.
- [ ] Запись банка со `status='draft'` не матчится никогда.
- [ ] Отозванная запись (`revoked_at`) не матчится.
- [ ] Запись с `approved_at` старше 90 дней не даёт `answer_now` — уходит в ревью.
- [ ] Вопрос возрастом 49 часов при пороге 48 не отвечается публично.
- [ ] Пять одинаковых вопросов в одном топике дают один ответ, а не пять.
- [ ] «Как убить рейд-босса» и «как убить время в походе» не матчатся на одну запись —
      регрессионный тест на стемминг, названный панелью как самый опасный узел.

## Implementation notes

- `CommunityAnswerMatcher::match(array $message, ?DateTimeImmutable $now = null)` принимает
  строку `community_messages` (не отдельную entity-обёртку — модель уже `returnType='array'`,
  заводить `CommunityMessage`-класс вне `## Files` было бы нарушением Закона 3). Опциональный
  `$now` — сеам для детерминированных тестов возраста (Non-goals требует воспроизводимость).
- `Decision` — value-object в том же файле (паттерн `Verdict`/`CommunityGuard.php`, story 07):
  `answer_now` / `answer_after_delay` / `receipt_only` / `silent`, плюс `escalated` и
  `coveredMessageIds` (список PK-строк, покрытых одним ответом — склейка дублей).
- Похожесть — коэффициент Жаккара по множеству грубых префиксных стеммов (слова ≥4 букв минус
  короткий стоп-лист вопросительных/служебных слов, стемминг = первые 3 символа, тот же приём,
  что `CommunityGuard::stems()`). "как убить рейд-босса" / "как убить время в походе" дают
  Жаккар ≈0.11 — общее "убить" тонет в остальных несовпадающих словах.
- Склейка дублей реализована через порядок `id`: у самого раннего открытого (`status='new'`)
  сообщения в топике, матчащегося на запись банка, — реальное решение с `coveredMessageIds`
  на все совпавшие; у более поздних дублей — `Decision::silent()` (уже покрыты). Работает
  зеркально для обеих полос.
- Отмена выдержки полосы B — отдельный публичный метод `isCancelledByHumanReply()` (не часть
  `match()`): решение о `answer_after_delay` — снимок момента матча, а человек может ответить
  позже, во время самой выдержки; вызывающий (story 09) обязан перепроверить прямо перед
  отправкой.
- Полоса A (`addressed_to_bot=1`) структурно не может вернуть `silent` — в коде для неё просто
  нет такой ветки, только `answer_now` (банк-текст либо `CommunityVoice::UNKNOWN`).
- Запись банка исключается из матча целиком (не просто «не участвует в счёте») при
  `status != 'approved'`, заполненном `revoked_at`, либо `approved_at` старше
  `community.answer.max_age_days` — устаревшая/неутверждённая запись для матчера как будто
  не существует, у полосы A это по-прежнему `answer_now` с `UNKNOWN`, у полосы B — `receipt_only`.
- Тест — изолированная схема `community_messages`/`community_answers` в `wildworld_tests`
  (паттерн `CommunityChatSenderTest`, story 06), не общая прод-схема.
