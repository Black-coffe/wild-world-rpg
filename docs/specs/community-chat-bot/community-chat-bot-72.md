# Аварийный режим провенанса не должен резать отправку

## Goal
`provenance_mode=deny` возвращает вето там, где решил ADR-178 — на одобрении, — и не глушит
авто-отправку молча.

## Requirements
> чтобы когда игроки что-то спрашивают, уточняют по игре, он отвечал, коммуницировал, комментировал, чтобы была живая группа

## Files
- app/Services/Community/CommunityGuard.php
- app/Controllers/Admin/CommunityController.php
- app/TaskHandlers/Community/CommunityAutoReplyHandler.php
- tests/unit/Services/CommunityGuardTest.php

## В чём дефект
Нашёл второй ревьюер. `CommunityGuard.php:263-273`: в режиме `deny` провенанс считается и денит
**на любом вызывающем**, включая тик авто-ответа. Докблок того же файла (`:31`) утверждает
дословно обратное: «на авто-отправке провенанс не считается никогда».

Это расходится не только с докблоком, но и с решением: ADR-178 говорит, что режим `deny`
возвращает вето **только на одобрении**. Инвариант оттуда же: на отправке пересчитывается лишь
то, состояние чего могло измениться после одобрения (килсвитчи, детерминированная лексика) —
корпус между одобрением и отправкой дрейфует, и провенанс там означал бы тихую смерть уже
одобренного ответа от правки `/guide`.

Сценарий: владелец в аварийном порядке ставит `deny`, чтобы ужесточить приём черновиков, —
и молча выключает половину уже одобренных ответов в чате.

## Non-goals
- Не менять поведение `advisory` и `off`.
- В тике и админке трогать **только строку вызова** `verdict()` — ничего больше в этих файлах.
- Не заводить второй метод-двойник: разделение по вызывающему — один явный параметр, а не копия логики.
- Не менять поведение по умолчанию в опасную сторону: дефолт параметра — **путь отправки** (вето провенанса не применяется). Забытый вызов обязан падать в безопасную сторону, а не глушить одобренный ответ.

## Acceptance criteria
- [x] В режиме `deny` вето применяется на одобрении и **не** применяется на отправке (`testProvenanceModeDenyRestoresTheOldVeto` / `testProvenanceModeDenyDoesNotVetoOnSendContextByDefault`).
- [x] Докблок описывает фактическое поведение всех трёх режимов.
- [x] Тест краснеет, если `deny` снова начнёт резать путь отправки (`testProvenanceModeDenyDoesNotVetoOnSendContextByDefault` проверяет allow при default-контексте).
- [x] Дефолт параметра — путь отправки: вызов без явного указания контекста не применяет вето провенанса.

## Implementation notes

- Нашёл РЕАЛЬНОЕ противоречие в исходном тексте story (различай по вызывающему одним параметром + не трогай вызывающих одновременно) и остановился с `NEEDS_CONTEXT`, не выбрав произвольно одну из двух несовместимых половин. Тимлид подтвердил ошибку и расширил `## Files`.
- `CommunityGuard::verdict()` получил 4-й параметр `bool $isApprovalContext = false` (последний, с default — обратная совместимость по позиции для любого стороннего кода, которого, впрочем, нет: только два известных вызывающих). Ветка `provenance_mode=deny` теперь денит, только если `$isApprovalContext === true`.
- `CommunityController::approveAnswer()` (`:290`) — передаёт `true` явно, единственное место одобрения.
- `CommunityAutoReplyHandler` (`:262`) — передаёт `false` явно (совпадает с default), не полагается на молчаливое умолчание — решение видно в диффе, а не подразумевается.
- В обоих файлах тронул РОВНО строку вызова `verdict()` + однострочный комментарий над ней — больше ничего (Non-goals).
- Докблок класса (рубеж 1) и докблок метода `verdict()` переписаны — старая формулировка «вызывающая сторона сама решает, когда звать verdict()» была ложью (тем самым дефектом, который нашёл второй ревьюер): на самом деле обе стороны ВСЕГДА зовут `verdict()`, различие теперь явное — параметром, а не тем, вызывают ли вообще.
- Проверил исполнением: `deny`+default(false) → allow; `deny`+explicit(false) → allow; `deny`+true → deny(`no_provenance`); `advisory`/`off` дают одинаковый результат независимо от `$isApprovalContext` (параметр их не касается вовсе).
- Прогнал `vendor/bin/phpunit --no-coverage --no-progress tests/unit/Services/CommunityGuardTest.php` (разрешено тимлидом для этой story) — 61/61 зелёных, 286 assertions.
