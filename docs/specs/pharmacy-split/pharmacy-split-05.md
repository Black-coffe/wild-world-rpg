# Подсказки о лечении перестают обещать еду там, где её больше нет

## Goal
Ни одна существующая точка входа не отправляет игрока за едой на полку, где еды нет.

## Requirements
> **UX-discoverability:** «🍲 Провизия» видна с экрана аптечки и наоборот **всегда**

## Files
- app/TaskHandlers/LowHealthWarningHandler.php
- app/Services/Events/EventMessageFormatter.php

## Что не так

Обе точки написаны до разделения полок и обещают то, чего на аптечке больше нет:

- `LowHealthWarningHandler` — текст предупреждения о низком здоровье прямо называет еду
  («аптечка/еда»), а единственная лечебная кнопка ведёт на `pharmacy`, где теперь только
  лекарства. По таблице в шапке `app/Config/Debuffs.php` еда лечит СИЛЬНЕЕ лекарств
  (Сытное рагу 45/55 против Аптечки 40/20) — то есть подсказка уводит от лучшего варианта
  ровно в тот момент, когда он нужнее всего.
- `EventMessageFormatter` — кнопка «🩹 Лечиться» после события с потерей здоровья ведёт туда же.

## Как

Рядом с «💊 Аптечка» поставить вторую кнопку «🍲 Провизия» (`callback_data: 'provision'`) —
обе точки лечения ведут на обе полки. Тексты, если называют еду, остаются честными;
если проще поправить формулировку — правь её, но кнопку на еду всё равно дай.

Прежде чем править, прогрепай по `app/` все места с `'callback_data' => 'pharmacy'` и
глазами проверь сопровождающий текст: если он обещает еду или сытость — это тот же дефект.
Правь ТОЛЬКО два файла из `## Files`; если нашёл третий — запиши путь и цитату в `## Findings`,
сам не трогай.

## Non-goals
- Не трогать карточку персонажа, карту, лагерь и квестовые хендлеры: там «💊 Аптечка» —
  обычная навигационная кнопка, она ничего не обещает про еду, а провизия достижима
  соседней кнопкой в один тап.
- Не менять `PharmacyAction` / `ProvisionAction` / `ConsumableShelfService`.
- Не менять числа лечения и не трогать баланс еды против лекарств.

## Map slice
`app/TaskHandlers/LowHealthWarningHandler.php` строки 120–145,
`app/Services/Events/EventMessageFormatter.php` строки 125–140.

## Acceptance criteria
- [ ] Из предупреждения о низком здоровье достижима полка провизии одной кнопкой.
- [ ] Из пост-событийной подсказки о лечении — тоже.
- [ ] Текст ни в одном из двух мест не обещает еду там, куда еда не ведёт.
- [ ] Клавиатура не даёт строк-одиночек после нормализации.

## Implementation notes

- `LowHealthWarningHandler.php`: клавиатура низкого HP теперь 3 кнопки (Аптечка/Провизия/Лекарства)
  через `ButtonPacker::pack()` вместо ручного массива рядов — гарантия «нет строк-одиночек»
  без ручного подсчёта. Финальная фраза `"...воспользуйся аптечкой."` → `"...аптечкой/провизией."`.
- `EventMessageFormatter.php::buildEndKeyboard()`: одиночная кнопка `🩹 Лечиться → pharmacy`
  заменена на пару `💊 Аптечка` + `🍲 Провизия` в одном ряду (2 кнопки — по правилу
  ButtonPacker строка-одиночка недопустима только для 1 кнопки, 2 в ряд и так ок, отдельный
  вызов пакера не нужен).
- Грепнул все `'callback_data' => 'pharmacy'` по `app/` (15 мест) — в остальных 13 файлах
  кнопка «💊 Аптечка» чисто навигационная, без обещаний про еду в сопровождающем тексте
  (подтверждено проверкой текста вокруг каждого вхождения) — они в Non-goals, не трогал.
