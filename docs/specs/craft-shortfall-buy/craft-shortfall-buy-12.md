# Замер: кто уже сегодня крутит цикл «купил сырьё → собрал → продал»

## Goal
Отдельный от фичи ответ на вопрос владельца. Появляется spark-команда, которая по логам считает
масштаб уже существующего цикла: сколько персонажей покупают сырьё и затем продают собранное из
него, сколько золота это печатает и на каких рецептах. Результат — отчёт с числами, по которому
принимается решение о судьбе 41 доходного рецепта.

## Requirements
> Отдельной задачей посчитать по логам: кто из живых игроков реально крутит цикл «купил сырьё → собрал → продал» и сколько золота это печатает.

## Files
- app/Commands/AuditCraftGoldLoop.php
- docs/specs/craft-shortfall-buy/audit-gold-loop.md

## Non-goals
- Ничего не чинить и не менять в экономике — это замер, а не правка.
- Не менять прайсы рецептов и не трогать `sales`.
- Не делать выводов о фиче докупки: цикл существует независимо от неё.

## Map slice
memory/map/craft.md, memory/map/admin.md; ADR-175 (счётчики банка затухают — «0» в них не означает «не покупали»).

## Acceptance criteria
- [ ] Команда считает по журналам действий, а не по затухающим счётчикам `resources_bank`.
- [ ] Отчёт называет: число персонажей с полным циклом, суммарное напечатанное золото, топ рецептов по марже, доля этих продаж в общем обороте.
- [ ] Когорты сравниваются в равном временном окне.
- [ ] Команда read-only: ни одного UPDATE/INSERT в игровые таблицы.
- [ ] Вывод не пропускается через `head`/`tail` в примерах запуска — это рвёт пайп и сыплет CRITICAL в лог.
- [ ] Отчёт зафиксирован в файле, а не только в выводе консоли.

## Implementation notes

- `app/Commands/AuditCraftGoldLoop.php` — read-only spark-команда `php spark audit:craft-gold-loop [--out PATH]`.
  Источник — журналы `transactions` (type=buy|sell) и `crafted_items_log` (завершения крафта), НЕ `resources_bank`.
  Равное окно = пересечение диапазонов покрытия всех трёх журналов. «Полный цикл» — слабая эвристика
  (buy+craft+sell одного персонажа в окне, sell не раньше первой buy) — точной FK-цепочки между журналами нет,
  это явно задокументировано в отчёте как метод, а не точный трейс.
  Маржа рецепта — оценка по каталогу (`crafted_items.price` минус стоимость сырья из `resources.buy_price`,
  с fallback на `crafted_items.price` полуфабриката); если хоть один ингредиент не находится ни в одном
  справочнике — маржа помечена «н/д», а не молча принята за 0.
- CI4 spark-опции парсятся как `--out value` (пробел), а не `--out=value` (проверено на этой версии CI4 —
  `=`-форма не сплитится, весь `out=...` уходит в имя ключа). CWD у `php spark` — `public/`, поэтому
  относительный `--out` пишет файл туда; для реального прогона использован абсолютный путь.
- `docs/specs/craft-shortfall-buy/audit-gold-loop.md` — реальный прогон на локальной БД (слепок testbot,
  устаревший: миграции остановились на batch 41-45 из ~500+, `player_action_log` в схеме нет вовсе).
  Итог: окно 2024-06-12..2024-06-17, 2 персонажа с полным циклом (n<20 — сигнала нет по правилу проекта),
  доля продаж полного цикла в обороте окна 100% (т.к. всего 3 продавца в этом узком окне). Отчёт честно
  называет размер выборки и не делает вывод по 41 рецепту — для этого нужен тот же прогон на актуальном
  дампе/на testbot.
