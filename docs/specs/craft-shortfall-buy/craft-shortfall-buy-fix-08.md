# Кнопка докупки не должна появляться там, где за ней нет рабочей сделки

## Goal
Экран нехватки может нарисовать кнопку докупки для рецепта, которого обработчик сделки не знает:
семь легаси-стартов брони и маяков не зарегистрированы в конфиге рецептов, и нажатие упрётся в
«Неизвестный рецепт». Кнопка обязана появляться только тогда, когда за ней стоит сделка, которая
реально пройдёт; иначе — честный замок с причиной и путём вперёд.

## Requirements
> сделать возможность крафтить даже если недостаточно какого-то материала или компонента для крафта вещи
> и процент налога за опт указываем в тексте, игрок должен видеть и понимать чего не хватает и сколько за это придлется заплатить!

## Files
- app/Services/Craft/CraftShortageService.php
- tests/unit/Services/Craft/CraftShortageServiceTest.php

## Non-goals
- Не регистрировать семь легаси-рецептов в конфиге рецептов: это отдельная контентная работа со своим риском.
- Не трогать `CraftShortfallBuyAction` и `CraftShortfallBuyService` — они закрыты предыдущими фиксами.
- Не менять порядок экрана: блок и кнопка остаются ниже «Добыть» и вариантов «собрать самому».
- Не убирать блок целиком: текст с раскладкой недостачи полезен и там, где докупка недоступна.

## Map slice

## Acceptance criteria
- [ ] Кнопка докупки появляется только для рецептов, которые обработчик сделки способен разрешить. Для остальных — замок с причиной, объясняющей, что докупка для этого рецепта пока недоступна, и что делать вместо неё.
- [ ] Тест краснеет, если кнопка снова начнёт появляться у рецепта, которого обработчик не знает.
- [ ] Для обычных рецептов поведение не изменилось: кнопка на месте, тесты предыдущих фиксов зелёные.
- [ ] Ни один игрок не может дойти до ответа «Неизвестный рецепт» через кнопку докупки.

## Implementation notes

`CraftShortageService::shortfallBuyBlock()`: кнопка докупки теперь требует не только распарсенный
`RecipeKey` из `craft_again_callback` (как раньше), но и `Config\CraftRecipes::get($recipeKey) !==
null` (новый приватный `knownToHandler()`) — тот же источник правды, каким резолвит рецепт
`CraftShortfallBuyAction::handle()`. Три состояния: ключа нет вовсе → поведение как раньше (fix-02,
кнопки не было, текст обычный, тест `...ShowsPositionsAndSummaryWhenAvailable` подтверждает); ключ
есть и известен обработчику → кнопка + обычный итог (`...ShowsWorkingButtonToEnterPurchase`); ключ
есть, но неизвестен обработчику (семь легаси броня/маяков fix-07) → кнопки нет, вместо итога — замок
`shortfallUnknownRecipeText()` с причиной и путём вперёд (позиции с ценами/кнопками добычи-докупки
выше остаются). Блок раскладки недостачи не убирается ни в одном из состояний.

Tips/guide-вердикт (правило `player-facing.md`): **нет** — это фикс невидимого игроку класса
дефекта (кнопка вела в «Неизвестный рецепт» только в узком случае, который редко наступал — fix-07
Findings), нет новой механики и нового пути; существующий совет/раздел про докупку у торговца
(если есть) не описывает эту частность.
