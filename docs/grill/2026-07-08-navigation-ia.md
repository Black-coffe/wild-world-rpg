# Грилл-бриф: пере-архитектура навигации Wild World (IA)

> Сессия 2026-07-08. Формат: два экспертных совета проектируют независимо и адверсариально грилят
> друг друга; независимый судья ранжирует; оркестратор (Claude) синтезирует единое решение.
> Линза: product. Владелец делегировал решение оркестратору («с меня толку нет — я не UX-практик»).
> Источник: workflow `nav-ia-two-councils-grill`, 9 агентов, 0 ошибок, ~851k токенов.

## 1. Проблема

Навигация выросла органически и хаотична (даже разработчик теряется). Триггер — реальная жалоба
игрока на Пикабу: «после "обучения" непонятно даже как просто ИДТИ».

Корни (audit-first):
- Постоянное reply-меню `[Перс · База · Крафт · Карта · Настройки]` смешивает типы сущностей
  (статус / место / система / вид-тупик / служебное) — нет единого принципа.
- Ядро-глаголы (двигаться, добывать, поход, квесты, аптечка, окопаться) НЕ на верхнем уровне —
  спрятаны в под-хаб «Действия» (путь: Перс → Действия). Верхнего входа к действию нет.
- «Карта» = статичное GD-фото без единой кнопки (тупик); настоящая ходьба живёт отдельно
  (Действия → Двигаться → компас).
- Масштаб графа: ~300 экранов, ~1167 переходов, глубина до 7, 9 точек входа, ~18 дублей «События»,
  дуал-хоминг (Оракул/Арена/Что-нового), фича-сироты (Боевой дрон).

## 2. Вердикт

**Победитель — гибрид: база проекта B + графты A.** Оба совета сошлись на ~90% каркаса (6 стабильных
reply-групп, Мир-first, слияние тупика-Карты с ходьбой, «Дела» поднимают квесты/таймеры,
locked-but-visible эндгейм, дедуп дублей, killswitch-миграция). Разница — в проработке самого
рискового механизма (поверхность ходьбы), где B объективно сильнее.

Оценки судьи (A / B): findability 8 / 8.5 · learnability 7.5 / 8.5 · scalability 7.5 / 8 ·
**telegram-fit 7 / 9 (решающий)** · consistency 8 / 8 · grounding 8 / 9.

## 3. Единое решение — новая IA

### Организующий принцип
Гибрид «место→действие» БЕЗ ложного лозунга «единой оси»: reply-каркас = **6 стабильных,
взаимоисключающих, названных-по-намерению назначений**. Инвариант не «одна ось», а «одна выученная
метка на частое намерение + один канонический дом на фичу» (ноль дуал-хоминга).

### Постоянное нижнее меню (reply, 2×3, стабильно всегда)
```
[ 🌍 Мир ] [ 🧑 Я ] [ 🔨 Крафт ]
[ 🏠 База ] [ 📋 Дела ] [ ⚙️ Ещё ]
```

### Группы верхнего уровня
- **🌍 Мир** — где стоишь и что делаешь ПРЯМО ЗДЕСЬ: компас-розетка ходьбы, добыть, поход,
  контекст-двери клетки (PvP/узел/NPC/поселение/обыск/событие), «🗺 Обзор мира» (редкое фото-карта),
  экран смерти/респавна.
- **🧑 Я** — кто я и что при мне: карточка, 🎒 инвентарь, «Все мои ресурсы», ⚔️ экип, 💊 аптечка,
  🧍 страховка (единый дом), 📊 Прогресс (достижения/титулы/серия/музей/экономика/рейтинг PvP→Арена).
- **🔨 Крафт** — всё руками: T1 без верстака / стандартный (Верстак 1) / профессиональный T3,
  сборка верстаков, специализация, модернизация, ремонт ИНСТРУМЕНТОВ.
- **🏠 База** — убежище: окопаться⇄телепорт, строить, постройки+апгрейд+ремонт ЗДАНИЙ, склад
  (объясняет карго-дрон), ангар (роботы/дроны/боевой дрон), грядки, декор, маяки, удалить/переезд.
- **📋 Дела** — что делать дальше и что в работе: 🌟 полярная звезда, квесты, задания дня,
  ⏱ активные таймеры (раньше только /tasks без кнопки), завершить готовое.
- **⚙️ Ещё** — реже нужное и растущее: 🛒 магазин/торговля, фракции/проект/реферал/подать,
  🏟 PvP-арена (канон)+рейтинг, 🔮 Оракул (канон), 🎮 развлечения, ❓ помощь (guide/tips/что-нового),
  ⚙️ настройки. Anti-junk-drawer: телеметрический инвариант эвакуации (порог в ADR) + «>7 секций → дробить».

### Три технических столпа (сердце решения, база B)
1. **Ходьба на ЛЁГКОЙ ТЕКСТ-поверхности** (`editMessageText`): media-on/off идентичны,
   `caption>1024` физически невозможен, `editMessageMedia` не дёргается на каждый шаг. Тяжёлое
   GD-фото карты вынесено в редкий отдельный экран «🗺 Обзор». (Прямая опора на баг-историю проекта:
   caption>1024 тихая потеря, editOrSend-регрессии, media-off-расхождение.)
2. **Компас = 3×3 розетка** (8 стрелок + центр = действие-на-клетке) как ОДИН гештальт-чанк
   (крестовина/WASD/roguelike), а не 8 выборов → снимает мнимую перегрузку 7±2.
3. **«Мир» не висит вечно**: reply `[🌍 Мир]` = re-summon-лаунчер; каждое прерывающее сообщение
   (событие/лут/тик Похода/re-attach) САМО несёт inline-крючок «🧭 Идти дальше». Стабилен REPLY-каркас;
   адаптивно INLINE-содержимое одного сообщения.

### Active-state и контекст
- Active-state честно НЕ подсветкой кнопки (reply не умеет), а **текст-заголовком** каждого экрана
  с эмодзи-якорем места: `🌍 Мир · 📍7:12, Лес · HP 80/100` (Nielsen #1 через текст, media-off-нейтрально).
- Cap-правило клетки: базовая поверхность = розетка(1) + [🥾 Поход] + [🗺 Обзор] = 3 чанка; двери клетки
  добавляются приоритет-порядком **опасность→ценность→социал**; при >3 дверях второстепенное сворачивается
  в «🔎 Ещё на клетке (N)»; абсолютный cap = 7. Архетипы клетки во многом взаимоисключающи (узел XOR
  поселение XOR strategic).
- Во время активного Похода розетка ЗАБЛОКИРОВАНА (случайный шаг/потеря прогресса невозможны).

### Slash-команды (не дублируют reply 1-в-1)
Якоря: `/start` (тяжёлый), `/menu` (лёгкий re-attach). Прыжки: `/go` (сразу к компасу — прямой ответ
«как идти»; `/world`,`/map` = алиасы), `/me`, `/base`, `/craft`, `/tasks`, `/quests`, `/shop`
(страховка демотированного Магазина), `/settings` (страховка Настроек). Помощь: `/guide`, `/tips`.

## 4. Самые острые удары прожарки (что сделало решение прочным)
Оба совета сошлись на одних и тех же фатальных рисках проекта-оппонента:
- **Плотность vs 7±2:** «на богатой клетке 15-18 кнопок в одном сообщении» → решено cap-правилом + розеткой-как-чанк.
- **Edit-in-place vs модель сообщений Telegram:** «~18 эмиттеров событий/таймеров/re-attach шлют НОВЫЕ
  сообщения → inline-Мир уезжает в историю» → решено re-summon-лаунчером + inline-крючком «Идти дальше».
- **Photo-vs-text ходьбы:** «editMessageMedia-вес + caption>1024 + media-off-ветвление» → решено текст-поверхностью.
- **Ложная «единая ось мест»:** Я/Крафт/Дела/Ещё — не места → принят честный принцип «назначения по намерению».
- **Демоут Магазина/Настроек без slash-фолбэка** → возвращены `/shop`, `/settings`.
- **Иконка 🎒 для «Я»** двусмысленна (рюкзак=инвентарь) → графт A: 🧑 для «Я», 🎒 строго инвентарю.

## 5. Decision log
- Ось IA: гибрid «место→действие», 6 стабильных reply-назначений 2×3. Почему: findability+learnability+
  scalability лучше плоского verb-бара и текущей смеси; стабильность reply > адаптивность (reply глобальна, смена = спам).
- Ходьба → текст-поверхность (editMessageText). Почему: обходит задокументированные регрессии проекта.
- Компас → 3×3 розетка. Почему: 1 гештальт-чанк вместо 8 выборов.
- Один канон на фичу, ноль дуал-хоминга. Почему: устраняет реальную путаницу (Оракул/Арена/Что-нового).
- Демотированные фичи страхуются slash-командами (/shop,/settings) + телеметрический инвариант эвакуации.

## 6. Ledger допущений
- ✓ (проверено кодом/историей) Reply глобальна и не умеет active-state/вложенность → текст-якорь обязателен.
- ✓ caption>1024 и editMessageMedia-вес — реальные боли (memory: photo_caption_1024, legacy_markdown).
- ✗ (не проверено) Игроки примут текст-ходьбу вместо фото-карты на каждом шаге → **Tier-3 cold-smoke 375px**.
- ✗ Реальная частота Магазина/Настроек (обоснование их места в «Ещё») → **телеметрия player_action_log** после выката.
- ✗ Взаимоисключающесть архетипов клетки (держит cap 7±2) → подтвердить у контент-дизайна + тест-инвариант на число дверей.
- ✗ Мир-first (статус во 2-й слот) лучше Я-first → подтвердить телеметрией частоты move+gather vs открытие карточки.

## 7. Risk register
| Риск | Митигация |
|---|---|
| Живые игроки не примут текст-ходьбу | Killswitch + Tier-3 cold-smoke + JIT-хинт «фото карты теперь в 🗺 Обзор» |
| «Мир» уезжает в историю | re-summon reply + inline «🧭 Идти дальше» на КАЖДОМ прерывании; unit на неизменность message_id в move-цикле |
| Богатая клетка пробивает 7±2 | cap-правило «🔎 Ещё на клетке (N)» + приоритет опасность→ценность→социал + тест числа дверей |
| Junk-drawer «Ещё» разбухнет | Телеметрический инвариант эвакуации (порог в ADR) + «>7 секций → дробить» |
| Миграция ~93 живым игрокам | Поэтапно за killswitch; лейблы «Я»/«Дела»/«Ещё» проверить cold-smoke на узнавание |

## 8. Residual ambiguity (0-10)
- Ясность цели: **8** (проблема и корни точны; спор только про порядок слотов).
- Покрытие дерева решений: **7** (каркас закрыт; открыты телеметрия-зависимые пороги и приёмка text-walk).
- Сила доказательств: **6** (архитектура опирается на баг-историю проекта; 2 допущения проверяются только выкатом/cold-smoke).

## 9. Следующий шаг
Оформить в ADR (🟠 — hard-to-reverse, есть trade-off) + implementation-plan по вертикальным слайсам.
**Слайс 1 = группа «🌍 Мир» с компасом-first** — он один закрывает жалобу Пикабу и является наименее
рискованным входом в пере-архитектуру. Далее «🧑 Я» (консолидация Перс+инвентарь+экип+аптечка+прогресс),
затем «📋 Дела», «⚙️ Ещё», «🔨 Крафт»/«🏠 База» — каждый за своим killswitch, с Tier-3 cold-smoke на чистом чаре.
