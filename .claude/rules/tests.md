# Тесты — ловушки

Перенесено из `memory/learnings/CONSOLIDATED.md` старого VULYK.

- Тесты, которые явно мокают каждую настройку, не покрывают дефолты: один кейс без оверрайдов и один, что гонит
  миграцию и сверяет посеянные значения с константами кода.
- `MockCache` игнорирует TTL (`get()` не проверяет срок, `getMetaData()` инвертирован) — истечение в unit не
  проверить. Проверять, что кэширование есть: считать SQL через событие `DBQuery` (N чтений → 1 запрос).
  Лгущий инструмент можно заменить, ассерт не ослаблять.
- Тест, который зовёт `telegram()`, стабит мост: локально проходит только из-за ключа в `.env`, на CI падает.
- Longman `Request::send()` под PHPUnit замыкается сам (`Request.php:698-702`): перехват отправок — через шов
  приложения `Request::send()`, не только `BridgeClient`.
- Ложно-красный полный набор — общее состояние: забытый `php -S`, два набора разом на `wildworld_tests`.
- Называть причину только после grep: однажды диагноз сослался на несуществующий `BaseConnection::$saveQueries`.
- CI гонит весь набор **одним процессом**, а локальные 10 частей — разными: зависимость от порядка видна только в
  CI (2026-11-25: 73 падения). Перед push после крупного мерджа — `vendor/bin/phpunit --no-coverage --no-progress`
  целиком одним процессом и без ключа, как на CI: `env 'telegram.API_KEY=' vendor/bin/phpunit --no-coverage
  --no-progress` (2026-11-26: тест «ERROR не пишется» ловил «Telegram init failed» моста — ключ теста через
  `putenv` в `setUp`). Тест, которому нужен настоящий Longman (без `PHPUNIT_TESTSUITE`), —
  `#[RunTestsInSeparateProcesses]`.
- Упавший внутри транзакции запрос CI4 не бросает, а оставляет `transStatus=false` на соединении до
  `resetTransStatus()` — следующий `transBegin()` его не сбрасывает. Код с `transBegin()` проверяет
  `transStatus()` до коммита, откатывает и сбрасывает; самодельная схема таблицы в тесте отстаёт от миграции
  молча (так `RuinLootCooldownReserveTest` отравлял все Web*-тесты).
